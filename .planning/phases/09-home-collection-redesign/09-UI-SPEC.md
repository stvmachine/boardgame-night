# Phase 9 — Home & Collection Redesign UI Design Contract

> Visual and interaction contract for the redesigned Home dashboard and Collection workspace. Generated by gsd-ui-researcher, verified by gsd-ui-checker. Hallmark anti-AI-slop critique applied on top of the existing Tabletop Social / Stitch design system.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | shadcn-vue CLI (reka-nova style) |
| Preset | reka-nova |
| Component library | reka-ui (headless accessibility primitives) |
| Icon library | Material Symbols Outlined via `@iconify/vue` |
| Font | Inter variable (`@fontsource/inter`) |

**Design system source:** Phase 5 tokens, primitives, and shell components are the only source of truth. No new design system, palette, font, or external UI package is introduced in this phase. Any new shadcn-vue scaffolds (Slider, ToggleGroup) must have their `@lucide/vue` imports replaced with the project's `Icon` wrapper.

---

## Spacing Scale

Declared values (multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline padding, thumbnail-to-text gaps |
| sm | 8px | Tight row gaps, card header/internal compact spacing, stat-row gaps |
| md | 16px | Card outer padding, section internal spacing, filter section gaps |
| lg | 24px | Layout column gap (`gap-6`), page padding, section vertical spacing |
| xl | 32px | Major section breaks between dashboard blocks |
| 2xl | 48px | Page-level top/bottom margins |
| 3xl | 64px | Hero landing spacing |

**Exceptions:** 44px minimum touch target for icon-only controls (mobile filter Sheet trigger, view-mode toggle, sort dropdown trigger, game-card nested action buttons).

**Phase-specific sizing values (also multiples of 4):**

| Element | Width | Notes |
|---------|-------|-------|
| Collection filter panel | 264px | Desktop sticky panel at `xl:` and above |
| Mobile filter Sheet | 300px (`sm:w-[300px]`) | Default Sheet width below sm |
| Mobile filter Sheet (sm+) | 360px (`sm:w-[360px]`) | Wider Sheet at `sm:` and above |
| Home trending card thumbnail | aspect-[4/3] | Same as GameCard and spotlight cards |
| List card thumbnail | 96px × 72px | `w-24 h-18` horizontal row |

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px | 400 | 1.5 |
| Label | 14px | 600 | 1.25 |
| Heading | 20px | 600 | 1.2 |
| Display | 28px | 600 | 1.2 |

**Badge:** 14px / 600 / 1.25, uppercase, letter-spacing 0.025em, small-caps.

**Micro-token exception:** `avatar-fallback-micro` — 10px / 600 / 1.0. Reserved exclusively for centered single-character fallback text inside avatars ≤ 20px. Not for body text.

**Type usage in this phase:**
- Home hero headline: `Display` (28px/600/1.2).
- Home hero subline / stats card title / trending section title / filter section headings: `Heading` (20px/600/1.2).
- Stat value numbers: `Display` (28px/600/1.2).
- Stat labels: `Label` (14px/600/1.25).
- Game card title: `Label` (14px/600/1.25), `line-clamp-2` in grid, `line-clamp-1` in list.
- Game card description: `Body` (14px/400/1.5) with `text-on-surface-variant` and `line-clamp-2`/`line-clamp-3`.
- Game card footer stats: `Label` (14px/600/1.25) or `Body` (14px/400/1.5) with `text-on-surface-variant`.
- Trending card rank: `Label` (14px/600/1.25).
- Empty/error helper text: `Body` (14px/400/1.5) with `text-on-surface-variant`.
- Filter labels, sort trigger, view toggle: `Label` (14px/600/1.25).

**Typography purity (Hallmark):** No italic headers. All headings and display type are roman (`font-style: normal`). Emphasis is carried by weight, accent color, or size, never by italic.

## Interaction & Layout Contracts

### Home Dashboard

**DOM order (source order):** `HomeHero` → `StatsCard` → `TrendingGames`.

**Desktop layout:**
- Top row: two-column grid `grid-cols-1 lg:grid-cols-12 gap-6`.
- Hero: `lg:col-span-8` — wide primary action card.
- Stats card: `lg:col-span-4` — narrow secondary context card to the right of the hero.
- Trending: full-width below, `pt-6` separator, `grid grid-cols-1 sm:grid-cols-2 lg:grid-cols-3 gap-6`.

**Mobile layout:**
- Stack hero → stats → trending with `space-y-6`.
- The merge action remains first in source order; the stats card stays in the same visual position but shows the sign-in prompt for signed-out visitors.

**Hero card:**
- Container: `Card` with `bg-surface-container` and `p-6`.
- Headline: `Display` (28px/600), no italic.
- Subline: `Body` (16px/400) `text-on-surface-variant` below headline.
- Input row: username `Input` + "Merge collections" primary `Button` side by side on desktop; stacked on mobile.
- Tags: horizontal wrapping flex of username pills below the input, each with a remove button. Use `Badge variant="draft"` or a custom surface pill with a close icon.
- Validation: inline `text-error text-sm` below the input; tags for invalid usernames show an error state and can be removed.
- Success: navigation to `/collection` with `usernames` permalink preserved.

**Stats card:**
- Signed-out: show heading "Sign in to see your stats", body text, and "Sign in" `Button variant="outline"` linking to `/login`.
- Signed-in: three stat columns in a single row on desktop; stacked on mobile.
- Each stat: value `Display` (28px/600) above a `Label` (14px/600) label.
- Loading: three `Skeleton` rectangles in place of values, with label skeletons below.
- Error: same as signed-out prompt but with the error message body.

### Trending Cards

- Six-card grid on Home; larger result set on `/hot` reuses the same component.
- Card: `Card` with `p-0 gap-0 overflow-hidden`, cursor pointer, hover `shadow-md` + `-translate-y-1` transition.
- Thumbnail: `aspect-[4/3] object-cover` with `bg-surface-variant` fallback showing "No image" centered.
- Rank badge: `Badge variant="draft"` positioned at top-left of thumbnail (or inline near title) with `#{rank}`.
- Body padding: `p-3`.
- Title: `Label` (14px/600), `line-clamp-2`.
- Meta row: BGG rating (with `material-symbols:star` icon or inline badge), weight, player range, play time.
- Missing enrichment fields render `—` (em dash), not `0` or blank.
- Click: open `https://boardgamegeek.com/boardgame/{id}` in new tab with `noopener,noreferrer`.
- "View all" link: top-right of section header, `text-primary text-sm font-medium hover:underline`, navigates to `/hot`.

### Collection Filter Workspace

**Desktop (`xl:` and above, 1280px+):**
- Layout: `flex flex-col xl:flex-row gap-6` inside `p-4 md:p-6`.
- Left panel: `aside.hidden.xl:block.w-[264px].xl:sticky.xl:top-6.xl:self-start`.
- Right area: `flex-1 min-w-0` containing toolbar (filter trigger, sort, view toggle) and results.
- Panel background: `bg-surface-container border border-outline rounded-xl p-4`.
- Panel sections: `space-y-6` with `border-t border-outline pt-6` between sections (except first).

**Mobile / tablet (below `xl`):**
- Filter panel hidden.
- Toolbar shows `Button variant="outline"` with `material-symbols:filter_list` icon and label "Filters".
- Sheet opens from the left with `w-[300px] sm:w-[360px]`.
- Sheet header: "Filters".
- Sheet content renders the same `CollectionFilterPanel`.

**Filter sections (top to bottom):**
1. **Search** — `Input` with `material-symbols:search` leading icon, `placeholder="Search"`, bound to `q`.
2. **Owners** — horizontal wrapping flex of owner avatar toggles. Each toggle is an `Avatar` button. Selected owners show `ring-2 ring-primary ring-offset-2`; unselected owners are at 50% opacity or muted.
3. **Players** — `PlayerRangeSlider` with a label showing the current range (e.g., "3–6 players" or "10+").
4. **Play time** — `TimeBucketCheckboxes` with `Checkbox` items for each bucket.
5. **Complexity** — `ComplexityToggleGroup` with four equal-width buttons.

**Active filter chips:**
- Rendered below the toolbar when any filter is non-default.
- Each chip is a small pill with the filter name and a remove icon.
- Trailing "Clear all" link/button.
- Empty selections mean no restriction; do not render chips for empty selections.

**Player range slider behavior:**
- Discrete steps 1–10.
- Label for `max === 10` renders as `10+`.
- A game matches when `game.minPlayers <= min && game.maxPlayers >= max` (supports the entire selected range).
- Default `null` means no restriction.
- Backward-compatible: old `players=N` permalink parses to `{min: N, max: N}`.

**Time bucket behavior:**
- Multi-select `Set<number>` of bucket values.
- OR semantics: a game matches if it matches any selected bucket.
- Empty set means no restriction.

**Complexity segmented control behavior:**
- Single-select: `null` (Any), `1` (Light), `2` (Medium), `3` (Heavy).
- Heavy covers both old `complexity=3` and `complexity=4`.
- Equal-width buttons; use `ToggleGroup type="single"` or controlled buttons with full keyboard support (arrow keys, roving tabindex, Enter/Space).
- Must be reusable by Phase 10.

### Sort & View Controls

**Sort control:**
- Dropdown/select or button-group with exactly four options:
  - `name_asc` → **Name A–Z**
  - `rating_desc` → **Rating High–Low**
  - `weight_asc` → **Weight Light–Heavy**
  - `recently_played` → **Recently Played**
- Trigger label: "Sort by: {selectedLabel}".
- Default: `name_asc`.
- Legacy sort values migrate per the research mapping; unknowns fall back to `name_asc`.
- Anonymous users see the same four options; "Recently Played" sorts games with no app history last, then by name.

**View mode toggle:**
- Two-button icon toggle using `ToggleGroup type="single"`:
  - `grid` → `material-symbols:grid_view`
  - `list` → `material-symbols:view_list`
- Default: `grid`.
- Persisted in URL as `view=grid|list`; invalid values fall back to grid.
- Toolbar order on desktop: "Filters" button (hidden xl) → `SortControl` → `ViewModeToggle`.
- On mobile, the same controls wrap; view toggle and sort may stack.

### Game Cards

**Common rules:**
- Both variants: `Card` with `rounded-xl`, `bg-surface-container`, `border border-outline`, `shadow-card`.
- Hover on interactive cards: `hover:shadow-md hover:-translate-y-1 transition-all duration-300`.
- Whole card is a clickable region that opens BGG in a new tab.
- Nested interactive controls (owner avatars, future action buttons) must stop propagation with `@click.stop` or equivalent.
- Description is plain text only; never use `v-html` on BGG description HTML.
- Thumbnail fallback shows "No image" centered in `text-on-surface-variant`.
- Owner avatars: `AvatarGroup` capped at 3 visible + `+N` overflow. Stack uses negative overlap (`-space-x-1`).
- Footer: three-column grid with `material-symbols:groups` (players), `material-symbols:schedule` (time), `material-symbols:fitness_center` (complexity/weight).

**Grid card:**
- Vertical layout.
- Thumbnail: `aspect-[4/3] object-cover` at top.
- Content: `p-3 space-y-2`.
- Title: `Label` (14px/600), `line-clamp-2`.
- Description: `Body` (14px/400), `text-on-surface-variant`, `line-clamp-2`.
- Rating badge: `Badge variant="invited"` with `average.toFixed(1)` if present.
- Weight badge: `Badge variant="draft"` with `averageWeight.toFixed(1)` if present.
- Owner stack below badges.
- Footer: `grid grid-cols-3 gap-1 text-xs text-on-surface-variant pt-1 border-t border-outline`.

**List card:**
- Horizontal layout.
- Thumbnail: `w-24 h-18 aspect-[4/3] object-cover rounded-lg` on the left.
- Content: `flex-1 min-w-0 p-3` with a right-side flex column.
- Title and badges row: title `line-clamp-1`, badges inline.
- Description: `line-clamp-3`.
- Footer and owner stack in the same bottom row; footer on the left, owner stack on the right.

### Skeletons

- Use `Skeleton` primitive with `bg-surface-variant` and `animate-pulse`.
- **Grid skeleton:** vertical shape matching grid card — 4:3 thumbnail rectangle, title line, description line, two badge rectangles, owner stack circles.
- **List skeleton:** horizontal row shape — 4:3 thumbnail rectangle on left, three text lines on right, two badge rectangles.
- Render the same number of skeleton items for grid and list (e.g., 12) to keep perceived density consistent.
- Stats card skeleton: three value rectangles + three label rectangles.
- Trending card skeleton: 4:3 thumbnail + title + meta line.
- Existing loading, error, empty, refresh, and queued-import states remain intact.

### Empty, Error, and Loading States

**Collection loading:**
- Render skeletons matching the selected view (grid or list).
- Keep the toolbar visible but disabled (or with sort/view disabled) during loading.

**Collection empty (no filters active):**
- Heading: "No games yet"
- Body: "Add a collector or start a new session to see games here." (reuse Phase 5 contract).
- CTA: "New Session" (if authenticated) or "Add collector" (if not).

**Collection no-results (filters active):**
- Heading: "No games found"
- Body: "Try adjusting filters or add a collector to see more games."
- CTA: "Clear filters" (resets all filters to default).

**Collection error:**
- Heading: "Couldn't load games"
- Body: "Please check your connection and try again."
- CTA: "Try again" triggers refetch.

**Queued import:**
- Heading: "Importing collection…"
- Body: "Games will appear as soon as the collection is ready."
- Show a subtle progress indicator or spinner.

**Home stats error:**
- Show the signed-out prompt with the error body instead of counts.

### Focus & Accessibility

- Focus ring: `focus-visible:ring-2 focus-visible:ring-primary focus-visible:ring-offset-2` on all interactive primitives.
- Visible focus only (`focus-visible`); no persistent focus rings on click.
- All icon-only buttons must have explicit `aria-label` (filter Sheet trigger, view toggle buttons, sort trigger, game-card owner stack, remove-tag buttons).
- `Slider` must expose two `<input type="range">` thumbs with correct `aria-valuemin`, `aria-valuemax`, `aria-valuenow`, and keyboard support (arrow keys, PageUp/PageDown, Home/End).
- `ToggleGroup` must support roving tabindex and arrow-key navigation.
- Sheet must have labelled `SheetTitle`, focus trap, and `aria-describedby` if needed.
- Game cards must be keyboard operable as a whole (use `<a>` or `<button>` with role semantics) while internal controls remain separately focusable.
- Heading hierarchy: page `h1` for Home hero headline; section titles `h2`; card titles `h3` where appropriate.
- Color contrast: all text uses `on-surface` / `on-surface-variant` over corresponding surface tokens.
- Motion: respect `prefers-reduced-motion: reduce`; card hover transforms collapse to ≤150ms opacity crossfade or no motion.

### Responsive Breakpoints

Verify at 320px, 375px, 414px, 768px, 1024px, and 1280px:
- No horizontal scroll (`overflow-x: clip` on `html` and `body`).
- Home hero input and button stack vertically below `md`.
- Stats card stat columns stack vertically below `lg`.
- Trending grid: 1 column below `sm`, 2 columns at `sm`–`lg`, 3 columns at `lg`+.
- Collection filter panel becomes a Sheet below `xl` (1280px).
- Collection grid columns: 1 below `sm`, 2 at `sm`–`md`, 3 at `md`–`lg`, 4 at `lg`–`xl`, 5 at `xl`+ (preserve existing grid density).
- Collection list view remains single column at all breakpoints.
- Game card titles never overflow; use `min-width: 0` and `overflow-wrap: anywhere` on display headers if needed.
- Image-bearing grid tracks use `minmax(0, 1fr)`, never bare `1fr`.

### Dark Mode

- Both light and dark palettes are generated from Phase 5 tokens; CSS custom properties switch automatically.
- The `ui` Pinia store exposes a `theme` field; the actual toggle UI is deferred to Phase 11.
- Until the toggle ships, the app renders in light mode by default.
- All new components must use semantic tokens (`bg-surface-container`, `text-on-surface`, etc.) so dark mode works without per-component changes.

## Token Class Reference

Use these exact Tailwind v4 classes (all map to Phase 5 M3 tokens) in the new components:

- **Page background:** `bg-surface text-on-surface`.

- **No hard-coded hex colors:** do not use `bg-indigo-*`, `text-neutral-*`, `bg-red-*`, etc. outside the token system.
