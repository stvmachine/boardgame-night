# Phase 9 — Home & Collection Redesign UI Design Contract

> Visual and interaction contract for the redesigned Home dashboard and Collection workspace. Generated by gsd-ui-researcher, verified by gsd-ui-checker. Builds directly on the Phase 5 "Tabletop Social" design system and the Phase 8 card/heading/responsive conventions.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | shadcn-vue CLI |
| Preset | reka-nova (from `components.json`) |
| Component library | reka-ui (headless accessibility primitives) |
| Icon library | Material Symbols Outlined via `@iconify/vue` |
| Font | Inter variable (`@fontsource-variable/inter`) |

**Design system source:** Phase 5 tokens, primitives, and shell components are the only source of truth. This phase adds `Slider` and `ToggleGroup` shadcn-vue/reka-ui primitives; no new external UI package or design-system dependency is introduced.

## Spacing Scale

Declared values (multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline badge/text gaps |
| sm | 8px | Tight row gaps, card internal tight spacing |
| compact | 12px | Card content padding, toolbar gap, filter label-to-control spacing, checkbox-to-label gaps, time-bucket item gaps, skeleton internal padding |
| md | 16px | Default element spacing, section internal spacing, filter section gaps |
| lg | 24px | Layout column gaps (`gap-6`), page padding, section vertical spacing |
| xl | 32px | Major section breaks between dashboard blocks |
| 2xl | 48px | Page-level top/bottom margins |
| 3xl | 64px | Hero-to-content landing breaks (Home only) |

**Exceptions:**
- 44px minimum touch targets for icon-only controls (Sheet close, mobile Filters button, view-toggle icons, card nested action triggers, owner remove buttons).
- 264px fixed width for the desktop Collection filter panel (constrained by D-09, not a spacing token).
- 56px × 56px stat-card icon containers (home stats).

**Phase-specific spacing values:**
- Page padding: `p-4 md:p-6` inside the main shell content area.
- Home dashboard block rhythm: `space-y-6` between hero+stats row and trending section; hero section uses `space-y-4` internally.
- Collection workspace column gap: `gap-6` between the filter panel and the results area.
- Filter panel internal section spacing: `space-y-6` between Search, Owners, Players, Time, Complexity.
- Filter section label-to-control spacing: `space-y-compact` (12px).
- Card grid gap: `gap-4`.
- Card content padding: `p-compact` (12px) for both grid and list cards.
- List card horizontal gap: `gap-4` between thumbnail and content.
- Footer-to-content spacing: `pt-2` / `border-t border-outline`.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px | 400 | 1.5 |
| Label | 14px | 600 | 1.25 |
| Heading | 20px | 600 | 1.2 |
| Display | 28px | 600 | 1.2 |

**Micro-token exception:** `avatar-fallback-micro` — 10px / 600 / 1.0. Reserved exclusively for centered single-character fallback text inside avatars ≤ 20px (`size="xs"` or `size="sm"`). Not for body text, labels, badges, or any other UI copy.

**Type usage in this phase:**
- Home hero title: **Display** role (28px/600/1.2), rendered as `text-[28px] font-semibold leading-tight text-on-surface`, `h1`.
- Home hero body: `Body` (16px/400/1.5) `text-on-surface-variant`.
- Section titles (`Trending on BGG`, `Upcoming sessions`, `Shared collection spotlight`): `Heading` (20px/600/1.2).
- Card title: `Label` (14px/600) `line-clamp-2` (grid) / `line-clamp-1` (list).
- Card description: `Label` size (14px/400) `text-on-surface-variant` rendered as `text-sm` `line-clamp-2` (grid) / `line-clamp-3` (list).
- Card footer stats: `Label` size (14px/600) `text-on-surface-variant` rendered as `text-sm font-semibold`.
- Filter section labels: `Label` (14px/600).
- Filter control text (checkbox labels, segmented buttons, sort trigger): `Body` (16px/400) or `Label` (14px/400) for chips.
- Badge labels (rating, weight): `Label` (14px/600), uppercase, tracking-wider, small-caps, per Phase 5 badge contract.
- Trending rank badge: `Label` (14px/600).
- Empty/error state headings: `Heading` (20px/600); body `Body` (16px/400) `text-on-surface-variant`.
- Stats card value: `Heading` (20px/600); label `Body` (16px/400) `text-on-surface-variant`.
- Avatar fallback for owner stacks (`size="xs"`): `avatar-fallback-micro` (10px/600/1.0).

Tokens are generated from the indigo seed `#4f46e5` using `@material/material-color-utilities` and committed as CSS custom properties in `app/frontend/entrypoints/styles.css`. Light values are listed; dark values switch automatically via the same variables.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `surface` / `background`: `#fcf8ff` (light) / `#131318` (dark) | Page background, main content area |
| Secondary (30%) | `surface-container`: `#f0ecf4` (light) / `#201f25` (dark) | Cards, sidebar, nav, filter panel, sheet, stat cards, game cards |

**Accent reserved for:** "Merge collections" button, "View all" link, active nav item, text links, focus rings, Invited status badge, active segmented control item, selected checkbox fill, selected slider thumb, active filter chips, and primary action buttons. **Not** for general body text, inactive icons, or secondary labels.

- Level 0: `bg-surface` — page background.

## Interaction & Layout Contracts

### App Shell Compatibility

- The existing Phase 5 shell (`AppShell.vue`, 280px `NavSidebar`, mobile `NavDrawer`) is unchanged.
- Collection filters **never** return to the global 280px sidebar; they live in the Collection-local 264px panel or the mobile Sheet (D-09).
- The `/hot`, `/collection`, and `/collection?group=<inviteCode>` routes remain reachable from the sidebar nav.
- Legacy permalink `/collection?usernames=...` and `/collection?group=<inviteCode>` continue to hydrate the correct state.

### Home Dashboard Layout

**DOM/source order (mobile and desktop):**
1. `HomeHero` — merge hero card.
2. `StatsCard` — personal stats or sign-in prompt.
3. `TrendingGames` — six-card trending preview.

**Desktop (`lg:` and above, 1024px+):**
- First row: a wide/narrow two-column layout (`grid grid-cols-1 lg:grid-cols-12 gap-6`):
  - Hero: `lg:col-span-8`.
  - Stats card: `lg:col-span-4`.
- Second row: `TrendingGames` at full width (`lg:col-span-12`) below the hero/stats row.
- Page padding: `p-4 md:p-6`.
- Max content width: fluid inside the shell main area; no additional `max-w-*` container.

**Mobile (< lg):**
- Stack hero → stats → trending vertically with `space-y-6`.
- The "Merge collections" CTA remains first (D-02).
- Hero title uses the Display role class `text-[28px] font-semibold leading-tight`; no 3xl/4xl custom sizes.

### Home Hero

- **Container:** `Card` with `CardContent` `p-6`.
- **Title:** Display role (28px/600/1.2), rendered as `text-[28px] font-semibold leading-tight text-on-surface`, `h1`.
- **Body:** `Body` (16px/400), `text-on-surface-variant`, `p`.
- **Input:** `Input` with label "Enter BoardGameGeek usernames" and placeholder "Type a username and press Enter".
- **Username tags:** inline flex wrap with `gap-2`; each tag is a `rounded-full` pill (`bg-surface-container-high border-outline` border, `px-2.5 py-1`) containing:
  - Validation spinner or status icon (`material-symbols:check`, `material-symbols:question_mark`, `material-symbols:close`) with tooltip.
  - Username text `text-on-surface`.
  - Remove button `material-symbols:close` with explicit `aria-label="Remove {username}"`.
- **CTA:** full-width `Button variant="primary"` label "Merge collections", disabled when `usernames.length === 0`.
- **Search section (remains from existing `UsernameForm`):** optional BGG search input, labeled "Search BGG games" with placeholder "Search games…". Same `Input` styling, results as a list of external BGG links; not the primary focus of the redesign.
- **Interaction:** Enter or comma adds a username; click/tap CTA navigates to `/collection?usernames=...` and updates the collector store.

### Stats Card

- **Container:** `Card` with `CardContent` `p-6`.
- **Signed-in state:**
  - Heading: "Your stats" (`Heading` 20px/600).
  - Three stat items in a horizontal row on desktop (`grid grid-cols-3 gap-4`), stacked vertically on mobile (`space-y-4`):
    - Each item: a `rounded-lg bg-surface-container-high` icon container (56×56px) with a Material Symbol, followed by the value (`Heading` 20px/600) and label (`Body` 16px/400 `text-on-surface-variant`).
    - Icons: collection `material-symbols:casino`, groups `material-symbols:groups`, sessions `material-symbols:calendar_month`.
  - Values are rendered from the dedicated `DashboardStats` GraphQL query; never derived from a cached collection query (D-04).
- **Signed-out state:**
  - Heading: "Sign in to see your stats" (`Heading` 20px/600).
  - Body: "Track your collection, groups, and game nights in one place." (`Body` 16px/400 `text-on-surface-variant`).
  - Link: `RouterLink` to `/login` with `text-primary` "Sign in".
- **Loading state:** three skeleton stat rows (icon circle + title line + label line) inside the card.

### Trending on BGG / Hot Cards

- **Home section container:** `Card` or plain section with `Heading` "Trending on BGG" and a trailing `RouterLink` to `/hot` with `text-primary` label "View all".
- **Home grid:** `grid grid-cols-2 sm:grid-cols-3 lg:grid-cols-6 gap-4` for exactly six cards.
- **Hot page grid:** reuse the same card; `grid grid-cols-2 sm:grid-cols-3 lg:grid-cols-4 xl:grid-cols-5 2xl:grid-cols-6 gap-4` for the larger result set (agent's discretion on exact count; default `/hot` limit is unchanged from the existing query).
- **Card anatomy:**
  - Rank badge: top-left overlay on the thumbnail, `Badge variant="draft"` with the rank number (e.g., `#1`).
  - Thumbnail: `aspect-[4/3]`, `rounded-lg`, `object-cover`, `bg-surface-variant`.
  - Fallback: "No image" centered in `text-on-surface-variant`.
  - Title: `Label` (14px/600), `line-clamp-2`, `text-on-surface`.
  - Meta line: `Label` (14px/400) `text-on-surface-variant` containing rating, weight, players, play time separated by middots. Missing values render as `—` (em dash).
- **Click behavior:** whole card opens `https://boardgamegeek.com/boardgame/{id}` in a new tab with `noopener,noreferrer`.
- **Loading state:** same grid with six card skeletons (thumbnail rectangle + title line + meta line).
- **Data contract:** enrich only from persisted `BggThing` via `HotItemThingLoader`; never live BGG calls (D-07).

### Collection Filter Workspace

**Layout:**
- Desktop (`xl:` and above, 1280px+): render `CollectionFilterPanel` inside a sticky `aside` with:
  - `class="hidden xl:block w-[264px] xl:sticky xl:top-6 xl:self-start space-y-6"`.
- Mobile / tablet (< `xl`): hide the aside; show a "Filters" trigger button in the toolbar that opens a `Sheet`.
- Sheet content (`side="left"`): `w-[300px] sm:w-[360px]` override class, `SheetHeader` with `SheetTitle` "Filters" and `SheetDescription` "Filter the shared collection".
- The filter panel uses the same `CollectionFilterPanel` component in both the desktop aside and the Sheet; state is the same Pinia store, so changes in either surface stay in sync.

**Toolbar (above results):**
- Mobile: "Filters" button (`Button variant="outline" size="sm"`) with icon `material-symbols:filter_list` and text "Filters".
- Sort trigger: `Select` primitive labeled "Sort" with four options.
- Group by trigger: `Select` primitive labeled "Group by".
- View toggle: `ViewModeToggle` with two icon-only items (`material-symbols:grid_view`, `material-symbols:view_list`).
- Active filter chips: rendered next to/after the controls when filters are active.
- Toolbar gap: `gap-compact` (12px), wrap on narrow screens (`flex flex-wrap`).

### Filter Panel Sections (in order)

1. **Search**
   - Label: "Search".
   - Control: `Input` with placeholder "Search games…" and icon `material-symbols:search` optional.
   - Debounce: 300ms (existing Fuse behavior).

2. **Owners**
   - Label: "Owners" with helper "Select whose games to include".
   - Quick actions: `Select all` and `Clear` link buttons (`text-primary` small text).
   - Owner list: horizontal wrapping avatar toggles (`flex flex-wrap gap-2`).
   - Each toggle is a `Button variant="outline"` or `Button variant="secondary"` (selected) containing `Avatar size="sm"` + `Label` username.
   - Selected state: `bg-primary-container text-on-primary-container border-primary` (or use `Button variant="secondary"` if it maps to primary-container).
   - Unselected state: `bg-surface border-outline text-on-surface`.
   - ARIA: each toggle button has `aria-pressed="true|false"` and an `aria-label="Include games from {username}"`.

3. **Players**
   - Label: "Players" with live value label on the right (`text-on-surface-variant`).
   - Control: `PlayerRangeSlider` two-thumb range, 1–10, step 1.
   - Value label: "{min}–{max} players" (render max as `10+` when max === 10); when min === max, render "{N} players" except N = 10 renders "10+ players".
   - Match semantics: game matches when `game.minPlayers <= selectedMin && game.maxPlayers >= selectedMax` (supports the entire selected range).

4. **Playing time**
   - Label: "Playing time".
   - Control: `TimeBucketCheckboxes` — six `Checkbox` items stacked vertically with `gap-compact` (12px).
   - Labels: ≤30 min, 30–60 min, 60–120 min, 120–180 min, 180–240 min, 240+ min.
   - Semantics: OR between selected buckets; empty selection means no restriction.

5. **Complexity**
   - Label: "Complexity".
   - Control: `ComplexityToggleGroup` — four equal-width buttons in a single row.
   - Options: Any (null), Light (1), Medium (2), Heavy (3).
   - Mapping (non-overlapping half-open ranges): Light [0, 2), Medium [2, 3), Heavy [3, ∞). UI labels remain **Light**, **Medium**, **Heavy**.
   - Keyboard: roving tabindex, arrow-key navigation, Enter/Space to select; clicking the selected "Any" item keeps it selected (no unselected state).

### Player Range Slider

- **Primitive:** shadcn-vue `Slider` (add if missing) or raw reka-ui `SliderRoot`/`SliderTrack`/`SliderRange`/`SliderThumb` if the shadcn wrapper lacks two-thumb support.
- **Model:** `PlayerRange | null` (`{ min: number; max: number }`). Default `null` renders the thumbs at 1 and 10 but does not apply a filter until the user interacts.
- **Range:** `min=1`, `max=10`, `step=1`.
- **Labels:** left = current min value; right = current max value (render `10+` when max is 10).
- **Keyboard:**
  - Left/right arrows move the focused thumb by one step.
  - PageUp/PageDown move by two steps.
  - Home moves to min; End moves to max.
  - Tab cycles between the two thumbs.
- **ARIA:** each thumb is an implicit `slider` role with `aria-valuemin`, `aria-valuemax`, `aria-valuenow`, and an `aria-label` ("Minimum players", "Maximum players").
- **Touch:** each thumb is at least 20px visual diameter (reka-ui default) and 44px hit area via an invisible `::after` or padding.

### Time Bucket Checkboxes

- Use the existing `Checkbox` primitive with `CheckboxIndicator`.
- Each item is a `label` wrapping the checkbox and text; `gap-compact` (12px) between checkbox and label.
- `text-on-surface` for label; `text-on-surface-variant` for optional helper text (none required).
- Checked state: `data-checked:bg-primary data-checked:text-on-primary data-checked:border-primary` (already in the Checkbox primitive).
- Focus: `focus-visible:ring-2 focus-visible:ring-primary/50` (built into Checkbox primitive).
- Empty selection = no restriction.

### Complexity Segmented Control

- **Primitive:** shadcn-vue `ToggleGroup` with `type="single"` (add if missing).
- **Controlled state:** internal model is `number | null`. The first item represents `null` ("Any"); the remaining items map to `1`, `2`, `3`.
- **Visual:** four equal-width buttons in a row, `rounded-lg` outer container, `border-outline` border, selected item `bg-primary text-on-primary`, unselected `bg-surface text-on-surface hover:bg-surface-container-high`.
- **Keyboard:** roving tabindex, arrow keys move focus, Enter/Space selects; clicking the already-selected item does nothing (single-select always has a value).
- **Reusability:** export as `ComplexityToggleGroup` for Phase 10.

### View Mode Toggle

- **Primitive:** `ToggleGroup` `type="single"`.
- Two icon-only items: grid (`material-symbols:grid_view`) and list (`material-symbols:view_list`).
- Selected item: `bg-surface-container-high text-primary`; unselected: `bg-surface text-on-surface-variant`.
- Each item has `aria-label="Grid view"` / `aria-label="List view"`.
- Default: grid.
- Persisted in URL as `view=grid|list` (D-15).

### Sort Control

- **Primitive:** `Select` with `SelectTrigger` and `SelectContent`.
- Trigger: label "Sort" + selected value + dropdown icon.
- Options: Name A–Z (`name_asc`), Rating High–Low (`rating_desc`), Weight Light–Heavy (`weight_asc`), Recently Played (`recently_played`).
- No descending name/weight options; legacy values map to the four options per the migration table.
- Recently Played is always enabled and functional; it is never disabled for anonymous users (D-18).

### Group By Toggle

- **Primitive:** `Select` with `SelectTrigger` and `SelectContent`.
- Trigger: label "Group by" + selected value + dropdown icon.
- Options: None, Number of Players, Rating Range, Best with X Players, Owner.
- Preserved from existing implementation; URL key `groupBy` (D-12).

### Active Filter Chips

- Rendered in the toolbar when any filter is active (search, player range, time bucket, complexity, owner subset).
- Each chip is a `Badge` or small `Button variant="outline"` with the filter value and a remove icon (`material-symbols:close`).
- Chips:
  - Search: `q: {text}` or just `{text}`.
  - Players: "{min}–{max} players" (or "{N} players" / "10+ players" for a single value at N=10).
  - Time: **one removable chip per selected time bucket**, each showing its label.
  - Complexity: "Light" / "Medium" / "Heavy".
  - Owners: avatar chip for each selected owner (or "N owners" summary chip).
- A trailing "Reset all" text button (`text-primary`) clears all filters and resets view to default but does not clear the group token or collector list.
- Clicking a chip's remove icon removes only that filter.
- ARIA: each chip has `aria-label="Remove {filter name} filter"` on the remove button.

### Rich Game Cards

**Card activation:**
- The whole card is a clickable region that opens the BGG page in a new tab (`window.open` with `noopener,noreferrer`).
- Use `role="link"` and `tabindex="0"` (or wrap in a `<button>`/`<a>`) so keyboard users can activate with Enter/Space.
- The card has `hover:shadow-md hover:-translate-y-1 transition-all duration-300`.
- **Nested controls must not trigger activation:** owner avatars, badges, sort controls, and future action buttons must call `event.stopPropagation()` (or be rendered as separate `<button>` elements with their own click handlers). Owner avatars are currently decorative only (no action), so they do not need to stop propagation unless made interactive in this phase.

**Grid card:**
- Outer: `Card class="cursor-pointer ... p-0 gap-0 overflow-hidden"`.
- Thumbnail: full-width `aspect-[4/3] object-cover bg-surface-container`.
- Fallback: same aspect container, `bg-surface-variant`, "No image" centered, `text-on-surface-variant`.
- Content: `CardContent class="p-compact space-y-2"`.
- Title: `h3` `text-sm font-semibold line-clamp-2 leading-tight text-on-surface`, `:title="name"`.
- Description: `p` `text-sm text-on-surface-variant line-clamp-2` (plain text; never `v-html`).
- Badges: `Badge variant="invited"` for rating (when present), `Badge variant="draft"` for weight (when present). Gap `gap-2`.
- Owner avatars: `AvatarGroup` capped at 3 visible + `AvatarGroupCount` `+N` overflow. Size `xs` (18px effective) for grid cards.
- Footer: `grid grid-cols-3 gap-1 text-sm font-semibold text-on-surface-variant pt-2 border-t border-outline` with three items:
  - Players: icon `material-symbols:groups` + `{{ playerLabel }}` (e.g., "2–4" or "1–5").
  - Time: icon `material-symbols:schedule` + `{{ timeLabel }}` (e.g., "60–120 min" or "30 min").
  - Complexity: icon `material-symbols:fitness_center` + `{{ weightLabel }}` (e.g., "2.4" or "—").
- Footer labels must handle null ranges gracefully: render "—" if both min and max are null; otherwise render the range with no spaces (e.g., "2–4").

**List card:**
- Outer: `Card class="cursor-pointer ... p-0 gap-0 overflow-hidden"`.
- Layout: `CardContent class="p-compact flex gap-4"`.
- Thumbnail: `w-24 aspect-[4/3] object-cover rounded-lg bg-surface-container flex-shrink-0` (96px wide, 4:3 ratio).
- Fallback: same size `bg-surface-variant` with "No image".
- Content area: `flex-1 min-w-0 space-y-2`.
- Header row (flex, gap-2): title `h3` `text-sm font-semibold line-clamp-1 text-on-surface` on the left; badges on the right (`flex-shrink-0 gap-2`).
- Description: `p` `text-sm text-on-surface-variant line-clamp-3`.
- Bottom row: `flex items-center justify-between`:
  - Footer stats (same three-column grid as grid card, but `gap-4` and inline spans; rendered `text-sm font-semibold text-on-surface-variant`).
  - Owner avatars on the right (`AvatarGroup` capped at 3 + overflow, `size="xs"`).

**Owner avatar stack:**
- Use `AvatarGroup` with `*:[data-slot=avatar]:ring-white` (override the primitive's `ring-background` if needed to ensure separation in dark mode).
- `AvatarGroupCount` uses `bg-surface-container-high text-on-surface-variant ring-white`.
- `Avatar size="xs"` for both grid and list cards.

### Recently Played Sort

- Sort option label: "Recently Played" (`recently_played`).
- Sort order: most recent non-cancelled `NightSession` that selected each game, descending by `lastPlayedAt`.
- Games without app play history sort last, then by name ascending (deterministic tie-break).
- In group mode, history is scoped to the group's sessions; in normal mode, to groups the current user can access; anonymous users get the same null history ordering (D-18).
- The `lastPlayedAt` field is added to `ThingFields` and resolved via `Loaders::LastPlayedAtLoader` (one query per collection request).

### Loading, Error, Empty, and Queued States

**Loading:**
- Show skeletons matching the selected view (grid or list) while the collection query is in its initial loading state.
- The toolbar (sort/view) is visible during loading; the filter panel is visible but disabled-looking (or enabled, but no owner list until loaded).
- Trending section shows its own skeletons.

**Error:**
- Use `EmptyState` with `material-symbols:warning` icon (fallback to `inbox` if not available), heading "Couldn’t load this page", body "Please check your connection and try again.".
- Do not retry automatically; user can refresh the page.
- Preserve the existing collection error state for backward compatibility.

**Empty (no collectors):**
- Heading: "No collectors selected".
- Body: "Enter one or more BoardGameGeek usernames to merge collections.".
- Show when `usernames.length === 0 && !groupMode && !loading`.

**Empty (no games after filters):**
- Heading: "No games found".
- Body: "Try clearing filters or selecting more collectors.".
- CTA: "Clear filters" `Button variant="primary"` when `hasActiveFilters` is true.
- Show when `filteredGames.length === 0 && !loading`.

**Queued / syncing imports:**
- Preserve the existing `CollectionView` polling behavior: when sync status is `QUEUED` or `SYNCING`, poll every 3 seconds and auto-trigger `importCollection` for queued collectors.
- Show a non-blocking inline status per collector below the toolbar or within the filter panel owner section (e.g., "Preparing collection for {username}…" / "Syncing {username}…").
- Do not block the rest of the UI during import.

### Heading Hierarchy

- Home page: `h1` for the hero title, `h2` for "Trending on BGG".
- Collection page: `h1` for the page title (optional, e.g., "Collection" if rendered), `h2` for grouped section names if grouping is active; otherwise no page heading required.
- Card titles are `h3` inside grouped sections or `h3` for ungrouped cards.
- Filter panel sections use `h3` or `legend` for section labels; because each section is a form region, a `legend` inside a `fieldset` is preferred for semantic grouping.
- Trending cards use `h3` for titles.
- Stats card heading is `h2`.

### Focus, ARIA, and Touch Targets

- Focus ring: `focus-visible:ring-2 focus-visible:ring-primary focus-visible:ring-offset-2` on all interactive primitives (Button, Input, Select trigger, Checkbox, ToggleGroup item, Slider thumb, Sheet close).
- Visible focus only (`focus-visible`); no persistent focus rings on click.
- Icon-only buttons must have explicit `aria-label` (Filters, Grid view, List view, Sheet close, Remove username, Remove filter chip, owner toggle).
- The player-range slider thumbs must expose `aria-label` and `aria-valuenow`.
- The complexity segmented control must behave as a single-select radio group: roving tabindex, arrow keys, Enter/Space selection.
- The Sheet must include `SheetHeader` with `SheetTitle` and `SheetDescription`; focus is trapped while open; Escape closes.
- Owner toggles use `aria-pressed` to communicate selected state.
- Active filter chips must be removable via keyboard (chip remove button is a focusable button with `aria-label`).
- Card activation must be keyboard-triggerable (Enter/Space on the card) and must not fire when focus is on a nested interactive control.
- Minimum 44×44px touch target for all icon-only controls (achieved via the Button `size="icon"` primitive or an explicit `min-w-11 min-h-11` class on icon-only buttons).
- Checkbox hit area: the entire `label` wrapping the checkbox and text is clickable; the checkbox itself is at least 16×16px with a 44px invisible touch area via `after:absolute after:-inset-x-3 after:-inset-y-2` (already in the Checkbox primitive).

### Reduced Motion

- Respect `prefers-reduced-motion`:
  - Disable card hover lift (`hover:-translate-y-1`) for users who prefer reduced motion; keep the shadow change.
  - Disable Sheet slide animation; use a simple fade or instant transition.
  - Skeleton pulse is acceptable as it does not convey meaning, but consider using `motion-reduce:animate-none` if it causes discomfort.
- Use Tailwind's `motion-reduce:` utilities where possible.

### Dark Mode Compatibility

- All colors must use M3 semantic token classes (`bg-surface`, `text-on-surface`, `bg-surface-container`, `border-outline`, `text-primary`, `text-error`, etc.).
- No hard-coded hex or Tailwind default colors (`bg-indigo-*`, `text-neutral-*`, `bg-red-*`, `text-white` overrides) except where Phase 5 explicitly mandates white avatar initials.
- Avatar group rings must be `ring-white` to maintain contrast on dark cards.
- Rating/weight badges reuse the semantic badge variants; do not introduce custom dark-mode overrides.
- The Sheet overlay uses the existing `SheetOverlay.vue` primitive (`bg-black/80`).
- Test both light and dark `color-scheme` values from `styles.css`.

### Source Order and Tab Order

- **Home DOM/source order:** hero → stats → trending. This is the mobile order and the desktop reading order.
- **Collection DOM/source order:** aside filter panel (desktop) / Sheet trigger (mobile) → toolbar → results → Sheet (when open). The filter panel is visually beside results on desktop but remains in source order before the results for logical tab flow.
- **Filter panel source order:** Search → Owners → Players → Time → Complexity.
- **Toolbar source order:** Filters button (mobile only) → Sort → Group by → View toggle → Active chips → Reset all.
- **Tab order:** follows DOM order. The slider thumbs are sequential tab stops. The Sheet, when opened, moves focus to the close button and traps focus.
- **Card tab order:** each card is a single tab stop; nested controls (if any) are separate tab stops. The list card has no additional nested controls by default, so it is a single tab stop.

## Token Class Reference

Use these exact Tailwind v4 classes (all map to Phase 5 M3 tokens) in the new components:

- **Page background:** `bg-surface text-on-surface`.
- **Cards:** `rounded-xl border border-outline bg-surface-container shadow-card`.
- **Card hover (interactive):** `cursor-pointer hover:shadow-md hover:-translate-y-1 transition-all duration-300 motion-reduce:hover:translate-y-0`.
- **Section title:** `text-xl font-semibold leading-tight tracking-normal text-on-surface` (equivalent to `Heading` 20px/600/1.2).
- **Text hierarchy:** `text-on-surface` primary; `text-on-surface-variant` secondary/helper; `text-primary` links/accent; `text-error` destructive.
- **Badges:** `Badge variant="invited"` for rating; `Badge variant="draft"` for weight; `Badge variant="draft"` for rank.
- **Buttons:** `Button variant="primary|outline|ghost|secondary|destructive" size="default|sm|icon"`.
- **Inputs:** `Input` (already styled with `border-outline bg-surface focus:ring-primary`).
- **Avatars:** `Avatar` with `useMemberColor(username)` class; `AvatarGroup` with `ring-white` override; `AvatarGroupCount` with `bg-surface-container-high text-on-surface-variant ring-white`.
- **Checkboxes:** `Checkbox` primitive.
- **Selects:** `Select` / `SelectTrigger` / `SelectContent` / `SelectItem`.
- **Sheets:** `Sheet` / `SheetContent` / `SheetHeader` / `SheetTitle` / `SheetDescription`.
- **Skeletons:** `Skeleton` with `bg-surface-variant`.
- **Divider:** `border-t border-outline`.
- **Focus ring:** `focus-visible:ring-2 focus-visible:ring-primary focus-visible:ring-offset-2`.
- **Compact spacing:** `p-compact` / `gap-compact` / `space-y-compact` (12px) are added to the `@theme` spacing scale; use them where the contract calls for 12px compact spacing.
- **No hard-coded hex colors:** do not use `bg-indigo-*`, `text-neutral-*`, `bg-red-*`, `text-white` (except avatar initials token or explicit white rings) outside the token system.
