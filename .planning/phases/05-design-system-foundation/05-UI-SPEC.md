# Phase 5 — Design System Foundation UI Design Contract

> Visual and interaction contract for the "Tabletop Social" design-system phase. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

## Design System

| Property | Value |

## Spacing Scale

Declared values (multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline padding |
| sm | 8px | Compact element spacing |
| md | 16px | Default element spacing |
| lg | 24px | Section padding |
| xl | 32px | Layout gaps |
| 2xl | 48px | Major section breaks |
| 3xl | 64px | Page-level spacing |

Exceptions: 44px minimum touch targets for icon-only controls (mobile menu toggle, drawer close button, nav icon buttons). *Default — no phase-specific exceptions.*

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px | 400 | 1.5 |
| Label | 14px | 600 | 1.25 |
| Heading | 20px | 600 | 1.2 |
| Display | 28px | 600 | 1.2 |

**Badge:** 14px / 600 / 1.25, uppercase, letter-spacing 0.025em, small-caps. *Labels and badges share the same weight and size to keep the type scale to two weights and four sizes.*

## Color

Tokens are generated from the indigo seed `#4f46e5` using `@material/material-color-utilities` and committed as CSS custom properties in `app/frontend/entrypoints/styles.css`. Light values are listed below; dark values are exposed via the same variables and switch automatically.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `surface` / `background`: `#fffbff` (light) / `#1c1b1f` (dark) | Page background, main surfaces |
| Secondary (30%) | `surface-container`: `#f0edf1` (light) / `#201f23` (dark) | Cards, sidebar, nav, elevated surfaces |
| Accent (10%) | `primary`: `#4d44e3` (light) / `#c3c0ff` (dark) | Primary CTA, active nav, links, focus rings, Invited badge |
| Destructive | `error`: `#ba1a1a` (light) / `#ffb4ab` (dark) | Destructive actions only |

Accent reserved for: New Session button, active nav item (icon + background pill), text links, focus rings, Invited status badge, and primary action buttons. **Not** for general body text or inactive icons.

## Component Inventory

### Primitives (build in this phase)

- **Button** — variants: `primary`, `secondary`, `outline`, `ghost`, `destructive`; sizes: `default`, `sm`, `lg`, `icon`.
- **Input** — text input with M3 `outline` border and `primary` focus ring.
- **Badge** — variants: `default`, `draft`, `invited`, `picking`, `completed`; all use `rounded-full` and small-caps 14px text.
- **Card** — `rounded-xl` (12px), `surface-container` background, 1px `outline` border, soft shadow (M3 elevation 1).
- **Avatar** — circular, deterministic per-username color from a tokenized M3 palette, white centered initials; sizes `xs` (18px), `sm` (20px), `md` (24px), `lg` (32px).
- **Skeleton** — `animate-pulse`, `surface-variant` background; shapes: `card`, `text`, `circle`, `rect`, `avatar`.
- **Icon** — wrapper around `@iconify/vue` for Material Symbols Outlined.
- **Dialog**, **Dropdown**, **Select**, **Tooltip**, **Tabs**, **Checkbox**, **Collapsible** — shadcn-vue/reka-ui primitives styled with M3 tokens.

### Layout (new shell components)

- **NavSidebar.vue** — 280px fixed desktop sidebar.
- **NavDrawer.vue** — mobile sheet/drawer using shadcn-vue Sheet.
- **AppShell.vue** — redesigned shell that composes NavSidebar/NavDrawer + main content area.
- **AppNav.vue** — nav item primitive (icon + label + active/hover states).

### Components to migrate / deprecate

- `AppShell.vue` → replace with new shell.
- `Sidebar.vue` → split: filters move into `CollectionView`; collectors move into `NavSidebar`; navigation moves to `NavSidebar`.
- `MobileDrawer.vue` → replace with `NavDrawer.vue`.
- `AppHeader.vue` → replace with mobile toggle embedded in `NavDrawer` trigger.
- `MemberAvatar.vue` → migrate to `Avatar` primitive with tokenized palette.
- `CollapsibleSection.vue` → migrate to `Collapsible` primitive.
- `ResultsSkeleton.vue` → migrate to `Skeleton` primitive.
- `EmptyState.vue` → keep as pattern, replace inline SVG with `Icon`.

## Interaction & Layout Contracts

### App Shell

- Desktop: fixed 280px sidebar on the left; main content area fills the remaining width with `md:ml-[280px]`.
- Mobile: sidebar is hidden; a hamburger toggle opens a full-height drawer from the left with a scrim overlay.
- Sidebar sections (top to bottom): full-width "New Session" primary button → nav items (`Home`, `Collection`, `Hot`, `Groups`, `Account`) → divider → collapsible "Collectors" section → spacer → `Settings` / `Logout`.
- When logged out, `Account` is replaced by `Log in` and `Sign up` in the bottom group.

### Navigation Items

- Each nav item shows a Material Symbol icon + text label.
- Hover: `surface-container-high` background.
- Active/current route: `primary-container` background + `primary` text/icon.
- Focus: 2px `primary` ring, 2px offset.

### Cards

- Outer container: `rounded-xl` (12px), `bg-surface-container`, 1px `outline` border, `shadow-sm` (M3 elevation 1).
- Hover on interactive cards: `shadow-md` + `-translate-y-1` transition (300ms).

### Badges

- Shape: `rounded-full`, horizontal padding `px-2.5`, vertical `py-0.5`.
- Typography: 14px / 600, uppercase, tracking-wider, small-caps.
- Status variants map directly to the semantic alias table above.

### Avatars

- Circular (`rounded-full`), white text, centered initial.
- Background color is deterministic based on `username` hash into a 15-slot M3 token palette (replaces hardcoded Tailwind colors in `useMemberColor.ts`).
- Border/ring: white 2px ring when stacked in an avatar group.

### Skeletons

- Use `animate-pulse` and `bg-surface-variant`.
- Game card skeleton must match `GameCard` layout: 4:3 thumbnail rectangle, two text lines (title + meta), two badge rectangles, and two stacked avatar circles.

### Icons

- All inline SVGs are replaced by the `Icon` component using Material Symbols Outlined names:
  - `AppHeader` hamburger → `material-symbols:menu`
  - `MobileDrawer` close → `material-symbols:close`
  - `CollapsibleSection` chevron → `material-symbols:chevron-right` (rotate on open)
  - `CollapsibleGroup` chevron → `material-symbols:chevron-right` (rotate on open)
  - `EmptyState` inbox → `material-symbols:inbox`
  - `HealthView` spinner → `material-symbols:progress-activity` (spin)

### Focus & Accessibility

- Focus ring: 2px solid `primary` with 2px offset.
- Visible focus only (`focus-visible`); no persistent focus rings on click.
- All interactive primitives must preserve reka-ui keyboard behavior (Enter/Space on buttons, Escape on dialogs/drawers, arrow keys in selects/tabs).
- Icon-only controls (mobile hamburger toggle and drawer close button) must have an accessible label: `aria-label="Open navigation"` for the toggle and `aria-label="Close navigation"` for the drawer close, or equivalent visually hidden text.

### Dark Mode

- Both light and dark palettes are generated now; CSS custom properties switch values automatically.
- The `ui` Pinia store already exposes a `theme` field; the actual toggle UI is deferred to Phase 11.
- Until the toggle ships, the app renders in light mode by default (`theme: 'light'`).

## Token Generation

- A one-time Node script `scripts/generate-m3-tokens.ts` runs `@material/material-color-utilities` with the seed `#4f46e5` and writes the full light/dark token set to `app/frontend/entrypoints/styles.css` inside the `@theme` block.
- The script is build-time only; the library is a dev dependency.
- Re-run the script only when the seed color changes.
