## Phase Goal

**As a** user of the boardgame night app, **I want to** navigate the app via a 280px sidebar with clear nav items and a prominent "New Session" button, **so that** I can easily move between surfaces and start a new boardgame night.

<objective>
Rebuild the app shell with the new Tabletop Social navigation: a 280px fixed desktop sidebar (NavSidebar) with icon+label nav items, a full-width "New Session" primary button, a collapsible Collectors section, and Settings/Logout at the bottom. Purpose: DS-02 requires the 280px sidebar with specific nav structure and mobile drawer. This is the visible shell that makes the design system tangible to the user. Per D-14 through D-18, filters move out of the sidebar (into CollectionView in Phase 9), collectors become a collapsible section, and new components are created alongside old ones.

</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| User interaction → navigation | Nav item clicks trigger route changes; RouterLink is safe (no window.open) |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-05-03 | Information Disclosure | Hamburger toggle + drawer close (icon-only controls) | medium | mitigate | aria-label="Open navigation" on hamburger trigger, aria-label="Close navigation" on Sheet close button (per UI-SPEC Focus & Accessibility, RESEARCH.md Pitfall 3) |
| T-05-04 | Tampering | Nav item route paths | low | accept | Nav item `to` props are hardcoded route paths from router/index.ts, not user-supplied; RouterLink validates routes |
| T-05-05 | Spoofing | Logout button | low | mitigate | Logout calls useAuth().signOut() which calls the GraphQL signOut mutation + clears Apollo cache + removes auth token; no client-side-only logout that could be bypassed |
</threat_model>
