<objective>
Upgrade the GraphQL contract from single-query to Apollo-batched queries. Switch the Vue Apollo client from `HttpLink` to `BatchHttpLink`, add the `params[:_json]` multiplex branch to `GraphqlController`, and verify end-to-end that batched health queries round-trip as a JSON array. Confirm that the security limits set in Plan 01-01 still protect the endpoint.

This is the second vertical MVP slice of Phase 1: when it completes, a developer can send multiple GraphQL queries in one HTTP POST and receive an array of results, with the schema enforcing depth/complexity limits and introspection disabled in production (GQL-04, FOUND-04 regression guard).

Per D-08 the security limits are hardcoded in `BoardgameNightSchema`; Plan 01-02 only verifies they continue to apply after multiplex is enabled. Per D-02 the schema and generated types stay committed.

Output: Apollo BatchHttpLink + Rails `Schema.multiplex` working end-to-end, with RSpec and Playwright proof.
</objective>

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-2-01 | Denial of Service | Apollo batched query abuse (multiple expensive queries in one POST) | medium | mitigate | `BoardgameNightSchema.max_complexity 400` and `max_depth 15` apply to the entire multiplexed request (graphql-ruby shares the complexity budget across the batch); `BatchHttpLink.batchMax: 25` caps the number of queries per batch on the client side |
| T-2-02 | Information Disclosure | GraphQL introspection enabled in production after controller change | high | mitigate | `BoardgameNightSchema.disable_introspection_entry_points` is guarded by `unless Rails.env.development? || Rails.env.test?` (D-08, implemented in Plan 01-01); Task 3 regression test verifies introspection is still rejected in production mode |
| T-2-03 | Tampering | `params[:_json]` branch bypasses `ensure_hash` parsing | low | mitigate | The multiplex branch passes `param[:variables]` through the existing `ensure_hash` helper, reusing the single-query string/Hash/ActionController::Parameters handling |
| T-2-04 | Information Disclosure | Apollo client `connectToDevTools: true` in production | low | mitigate | `connectToDevTools: import.meta.env.DEV` is already set in Plan 01-01; Task 3 verifies this line is unchanged |
| T-2-SC | Tampering | npm packages for Apollo batch link | high | mitigate | `@apollo/client/link/batch-http` is part of the authoritative `@apollo/client` package (verified in RESEARCH.md Package Legitimacy Audit as a false-positive SUS with 7M+ weekly downloads and apollographql/apollo-client source repo); no human-verify checkpoint needed |
