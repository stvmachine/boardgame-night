# Phase 1 — UI Design Contract

> Visual and interaction contract for the foundation shell phase. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Phase UI Scope (read this first)

Phase 1 delivers **plumbing and contract, not domain features**. The only UI surface is:

1. **Vue SPA shell** — root `<App>` + `<RouterView>` + one route/view that later phases (3/4) build domain features into.
2. **Health query view** — renders the result of the one GraphQL query (proves the Rails ↔ Vue Apollo contract per FOUND-02 / GQL-01 / GQL-04).
3. **Three query states** — loading, success, error (proves Apollo client wiring + error handling).

There are **no domain UI components** in this phase: no collections, no search, no forms, no auth screens, no boardgame night sessions. Do NOT invent domain features. This contract locks the **shell** (layout container, typography baseline, color tokens, the one health-view's states) that later phases extend.

**UI-relevant requirement IDs:** FOUND-02, GQL-01 (SPA renders talking to `/graphql`); GQL-04 (Apollo batched query round-trips). The remaining Phase 1 requirements (FOUND-01, 03, 04, 05) are infrastructure/security/deploy — not UI.

**Health query shape is a planning discretion item** (CONTEXT.md D-06: string vs JSON vs structured `HealthCheck` type). For UI purposes this contract assumes a `health` query returning at minimum a `status: String` field; planning confirms the exact shape. The success-state render is shape-agnostic (displays the returned payload as readable text).

No `tailwind.config.js`. Spacing/typography/color values map directly to Tailwind v4's default 4px-based scale (`p-4` = 16px, `text-base` = 16px, etc.).

## Spacing Scale

Declared values (multiples of 4 only). Aligns with Tailwind v4's default 0.25rem (4px) step.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline padding (none in Phase 1) |
| sm | 8px | Compact element spacing, badge padding |
| md | 16px | Default element spacing, health-view padding |
| lg | 24px | Section padding, view vertical rhythm |
| xl | 32px | Layout gaps, shell outer padding |
| 2xl | 48px | Major section breaks (none in Phase 1) |
| 3xl | 64px | Page-level spacing (none in Phase 1) |

Exceptions: none. No icon-only touch targets in this phase (no interactive controls beyond focus rings).

## Typography

Four sizes, two weights. System font stack (no web font load in Phase 1 — keep the shell fast; Phase 3 may introduce a brand font).

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px | 400 (regular) | 1.5 |
| Label | 14px | 600 (semibold) | 1.4 |
| Heading | 20px | 600 (semibold) | 1.2 |
| Display | 28px | 600 (semibold) | 1.2 |

- Body = health-view result text, default paragraph copy.
- Label = status badges ("OK", "ERROR"), small captions.
- Heading = view section title (e.g., "Server Health").
- Display = shell/app title if shown (e.g., app name in the shell header).
- Monospace (`font-mono`, Tailwind default stack) for any raw query-payload display in the success state.

## Color

Light theme only for Phase 1. Dark mode is a Phase 3+ concern (the collection surface will need it). Tailwind v4 `@theme` tokens.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#ffffff` (white) | App background, shell canvas |
| Secondary (30%) | `#f5f5f4` (neutral-100) | Health-result panel, cards, nested surfaces; `#ffffff` for inner cards |
| Accent (10%) | `#4f46e5` (indigo-600) | Health-status "ok" badge, focus-visible rings, loading spinner stroke |
| Destructive | `#dc2626` (red-600) | Error-state indicator + error text only |

**Accent reserved for:** health-status "ok" badge, `:focus-visible` outline on interactive elements, loading spinner stroke.

**Accent is NOT used for:** body text, headings, backgrounds, borders (use neutral palette).

> ⚠️ **Placeholder brand color.** Indigo-600 is a default chosen for contrast/accessibility on white (WCAG AA at 16px+). It is **revisitable in Phase 3** when the collection surface introduces owner color-avatars (COLL-09 needs a deterministic per-username palette) and a real brand identity. Do not over-commit to indigo across domain components yet.

## Copywriting Contract

Phase 1 has **no user actions** (no forms, no CTAs, no destructive operations). The copy contract covers the three health-query states only — these prove the Apollo client wiring (loading / success / error).

| Element | Copy |
|---------|------|
| Primary CTA | none — no user actions in this phase |
| Empty state heading | N/A — health query always returns a result or errors; no "no data" state exists |
| Empty state body | N/A |
| Loading state | "Connecting to server…" (with a spinner; proves Apollo `loading` state wiring) |
| Success state | Renders the query payload as readable text; heading "Server Health" + the returned `status` field (e.g., "ok"). Shape-agnostic — D-06 confirms exact fields during planning. |
| Error state (heading) | "Couldn't reach the server." |
| Error state (body) | "Make sure Rails is running on localhost:3000, then reload the page." |
| Destructive confirmation | none in this phase |

**Copy voice:** developer-facing for this phase (the health view is a dev contract probe, not a user feature). Phase 3+ copy becomes user-facing.

## Shell Layout Contract

The shell is the container later phases restructure. Lock it minimal now.

- **Root:** `<App>` component with `<RouterView />` (vue-router 5.1.0, lazy-loaded routes per STACK.md).
- **Layout:** single full-viewport-height container (`min-h-screen`, neutral dominant background), content centered horizontally, max-width `640px` (Tailwind `max-w-xl`), vertical padding `32px` (xl).
- **Health view:** centered card (secondary surface, `rounded-lg`, `p-6` = 24px) containing the heading + status badge + payload text.
- **Do NOT over-build the shell.** No sidebar, no header bar, no nav, no footer in Phase 1. Phase 3 introduces the desktop sidebar + mobile drawer + responsive grid (COLL-16); Phase 4 adds auth-aware nav. The shell here is intentionally a blank centered canvas so those structures attach cleanly later.
