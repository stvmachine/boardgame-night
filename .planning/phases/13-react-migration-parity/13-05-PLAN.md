<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Invite URL → session preview | A bearer-like token authorizes intentionally limited preview data. |
| Authenticated viewer → RSVP mutation | Identity and token cross the Rails authorization/validation boundary. |
| Past-session query → viewer | Group membership controls access to history. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-13-05-01 | Elevation of Privilege | Invite RSVP | high | mitigate | Require AuthContext for controls while relying on Rails to validate session token, user, and response; cover signed-out UI negatively. |
| T-13-05-02 | Information Disclosure | invite preview | medium | accept | Session title/group/host/date/location are intentionally shareable with a valid invite; render no collection/member data. |
| T-13-05-03 | Information Disclosure | past sessions | high | mitigate | Query through authorized `group(token)` and do not fall back to unscoped history. |
| T-13-05-04 | Tampering | RSVP cache update | medium | mitigate | Use only mutation-returned identities/state and de-duplicate attendance references. |
| T-13-05-05 | Repudiation | RSVP confirmation | low | accept | Server persistence is authoritative; UI confirms returned response and exposes failures without claiming success. |
</threat_model>
