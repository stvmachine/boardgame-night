<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Viewer → group manager controls | Client role display crosses a server-enforced authorization boundary. |
| Invite token → clipboard/email | Shareable capability and recipient address leave the current UI. |
| Mutation response → Apollo cache | Server-returned identities update normalized group/session state. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-13-04-01 | Elevation of Privilege | membership/create/invite controls | high | mitigate | Match shipped role visibility for usability, but call only Rails mutations that re-authorize every operation; add negative component cases. |
| T-13-04-02 | Information Disclosure | Group sessions/collection | high | mitigate | Render only GetGroup's authorized fields; do not issue a parallel unscoped collection query. |
| T-13-04-03 | Tampering | Apollo mutation reconciliation | medium | mitigate | Cache only mutation-returned ids/entities or refetch the scoped group; never synthesize privileged roles. |
| T-13-04-04 | Information Disclosure | invite link/email | medium | accept | Link is intentionally shareable and email is required for invitation; do not log either value client-side. |
| T-13-04-05 | Tampering | external spotlight link | medium | mitigate | Use backend objectid, React escaping, and `noopener noreferrer`. |
</threat_model>
