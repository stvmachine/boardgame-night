# Phase 04 — UI Design Contract

> Visual and interaction contract for the auth, friend groups, and boardgame-night session lifecycle surface. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

## Design System

| Property | Value |
|----------|-------|
| Tool | none (Tailwind CSS v4 CSS-first is the styling layer) |
| Preset | not applicable |
| Component library | Tailwind utility classes + project-specific Vue components (no headless UI library) |
| Icon library | inline SVG only (no icon dependency) |
| Font | Tailwind default sans-serif stack (Inter / system-ui / sans-serif) |

## Spacing Scale

Declared values (multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline padding, badge padding |
| sm | 8px | Compact element spacing, input padding y, card gap |
| md | 16px | Default element spacing, section padding, form gap |
| lg | 24px | Section padding, page content gaps |
| xl | 32px | Layout gaps, major card margins |
| 2xl | 48px | Hero/empty state vertical spacing |
| 3xl | 64px | Page-level spacing |

Exceptions:
- 44px minimum hit area for icon-only buttons (e.g., mobile menu toggle, remove buttons).
- 280px fixed width for the desktop sidebar.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px | 400 (regular) | 1.5 |
| Label | 14px | 600 (semibold) | 1.4 |
| Heading | 20px | 600 (semibold) | 1.2 |
| Display | 28px | 600 (semibold) | 1.1 |

Notes:
- Body text is the default for all readable paragraphs and form helper text.
- Labels use the semibold weight to distinguish form labels, section headers, and metadata keys.
- Headings are used for card titles, page section titles, and empty-state headings.
- Display is reserved for page hero headings (e.g., HomeView title).

| Accent (10%) | #4f46e5 | Primary actions, links, focus rings, selected states, badges |

Accent reserved for:
- Primary action buttons (e.g., “Sign up”, “Create group”, “Create a night”, “Send invite”).

## Interaction Contract

### Auth & navigation
- Bearer token lives in JS memory (Pinia auth store) and is attached by the Apollo `setContext` link; no `localStorage`.
- Unauthenticated users visiting protected routes (`/groups`, `/g/:token`, `/s/:id`, `/account`) are redirected to `/login` with `redirectTo` preserved.
- Header nav gains **Groups** and **Account** links when authenticated; anonymous users see **Home**, **Collection**, and **Hot** plus **Log in** / **Sign up**.
- Log out is reachable from any page via the header account menu and destroys the session on the server.

### Forms & validation
- Form labels use `text-sm font-medium text-neutral-700` (Label role).
- Inputs use `border-neutral-300`, `focus:border-indigo-500`, `focus:ring-2 focus:ring-indigo-500`.
- Primary submit buttons are `bg-indigo-600` text-white; disabled state uses `bg-neutral-300 text-neutral-500`.
- Inline validation errors appear below the relevant field in `text-sm text-red-600`.
- Global mutation errors appear in a `rounded-md border border-red-200 bg-red-50 p-3 text-sm text-red-700` alert.

### Group & session management
- Group creation opens as a simple form (no modal required) on `/groups` or a dedicated `/groups/new` route.
- Invite links are surfaced in a read-only input with a **Copy link** button; copying shows a brief `text-indigo-700` success hint.
- Session state is communicated with a status badge:
  - `draft` — `bg-neutral-100 text-neutral-700`
  - `invited` — `bg-indigo-100 text-indigo-800`
  - `picking` — `bg-amber-100 text-amber-800`
  - `completed` — `bg-green-100 text-green-800`
- Host transitions (`Schedule`, `Start picking`, `Pick game`, `Cancel`, `Reopen`) are primary or secondary buttons at the top of the session page.
- The game picker reuses the existing collection grid with an additional player-count filter constrained by the number of attending guests.

### RSVP (no-account)
- The `/invite/:token` landing page shows the session title, host, date/location, and two equal-width buttons: **Going** (indigo) and **Not going** (neutral outline).
- Selecting **Going** reveals an optional “Name your nickname” field; submit uses the primary CTA style.
- After RSVP, the page shows a confirmation summary and a read-only attendee count.

### Destructive actions
- All destructive actions trigger a confirmation step. The first click exposes a compact confirmation area (inline or modal) containing the destructive copy above; the final action uses a `bg-red-600 hover:bg-red-700 text-white` button.
- No destructive action is executed on the first click.
