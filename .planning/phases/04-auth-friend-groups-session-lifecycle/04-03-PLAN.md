## Phase Goal

**As a** group host, **I want to** create boardgame night sessions and send magic-link invitations, **so that** my friends can RSVP without creating accounts and I can see who is coming.

<objective>
Deliver the sessions + RSVP vertical slice: NightSession + Attendance models, 4-state lifecycle (draft → invited → picking → completed), createNightSession/scheduleSession/rsvp/upgradeToAccount mutations with dry-validation contracts, session invite magic links via the existing InviteToken table, provisional User creation for no-account RSVP, and Vue session editor + RSVP dashboard + invite landing page.

Purpose: This is the core night-organizing surface. The provisional user pattern (ADR-009) lets invitees RSVP without friction, and the InviteToken table (ADR-010) is reused for session invitations.

Output: Working session creation, invitation, RSVP, and host dashboard flow end-to-end with RSpec model+mutation+mailer specs.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Email → Magic link → Client | Untrusted token redemption; /invite/:token is a public route for RSVP |
| Client → GraphQL API | RSVP mutation is unauthenticated (no Bearer token needed); all other session mutations require auth |
| Provisional user → Full account | Upgrade path crosses trust boundary; must validate email+password |
