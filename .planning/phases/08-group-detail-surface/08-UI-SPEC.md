## Spacing Scale

Declared values (multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Inline avatar/text gaps, icon-only button padding |
| sm | 8px | Tight row gaps, card header/internal compact spacing |
| md | 16px | Card outer padding, section internal spacing |
| lg | 24px | Layout column gap (`gap-6`), page padding, section vertical spacing |
| xl | 32px | Major section breaks between hub blocks |
| 2xl | 48px | Page-level top/bottom margins (not used inside cards) |
| 3xl | 64px | Hero/page landing spacing (not used here) |

**Exceptions:** 44px minimum touch target for the invite-link copy icon button and member-row action-menu trigger on mobile.

**Phase-specific spacing values:**
- Page padding: `p-4 md:p-6` inside the main shell content area.
- Hub block vertical rhythm: `space-y-6` between the header, sessions card, spotlight card, and the stacked mobile sections.
- Two-column layout gap: `gap-6` on `lg:grid-cols-12`.
- Session row padding: `p-4`.
- Date block: `h-14 w-14` (56px).
- Spotlight thumbnail: `aspect-[4/3]` with `rounded-lg`.
- Compact owner avatars: `size-5` (20px) with `text-[10px]` fallback.

## Interaction & Layout Contracts

### Responsive Layout

- **DOM order (mobile and source order):** `GroupHeader` → `GroupSessionsList` → `GroupCollectionSpotlight` → `GroupMembersPanel` → `InviteCard`.
- **Desktop (`lg:` and above, 1024px+):** full-width header above a two-column grid:
  - `grid grid-cols-1 lg:grid-cols-12 gap-6`
  - Main column: `lg:col-span-8 space-y-6` containing sessions and spotlight.
  - Side rail: `lg:col-span-4 space-y-6 lg:sticky lg:top-6 lg:self-start` containing members and invite card.
- **Sticky guard:** The side rail is sticky only at `lg:` and above and only when `self-start` prevents overflow. On smaller viewports the rail stacks with the rest of the content and is not sticky.
- **Max content width:** No extra max-width container is added; the hub lives inside the existing main-shell content area with `p-4 md:p-6`.
- **Column ratio:** 8/4 main-to-rail. Do not use 9/3 because the rail must fit the invite form and member menu.

### Group Header

- **Desktop:** a single horizontal row: group name on the left, "Create a night" button on the right. The description and member count badge sit beneath the name.
- **Mobile (< lg):** the "Create a night" button becomes a full-width primary button directly below the description (DOM order after description). It is **not** right-aligned on mobile.
- **Member count badge:** neutral pill (`Badge variant="draft"` or `bg-surface-container-high text-on-surface-variant`), placed inline next to the group name on desktop and below the name on mobile.
- **Description:** `text-on-surface-variant`, `Body` size, optional (hidden if null/empty).
- **Permissions:** "Create a night" is visible only when `group.myRole === 'OWNER' || group.myRole === 'ADMIN'`. Do not broaden creation permissions.
- **Iconography:** "Create a night" button may optionally include `material-symbols:add` at `size-4` before the label.

### Upcoming Sessions List

- **Container:** `Card` with `CardHeader` title "Upcoming sessions" and `CardContent`.
- **Row structure:** each row is a `Card` (`bg-surface-container-high` or `bg-surface-container` with hover `bg-surface-container-high`) with:
  - Left: date block (56×56px, `rounded-lg`, `bg-surface-container`, centered).
  - Middle: session title (`Body` semibold), optional scheduled time, status badge.
  - Right: attendee count (avatar stack + `Label` text) and a trailing state-aware CTA button.
- **Date block:**
  - Month: `Label` uppercase, `text-on-surface-variant` (e.g., "JUL").
  - Day: `Heading` 20px, `text-on-surface` (e.g., "15").
  - Drafts with no `scheduledAt` display "Date TBD" in place of the date block, using the same container but with two stacked `Label` lines "Date" and "TBD".
- **Row click:** the whole row navigates to `/s/:id` via `router.push`. The trailing CTA is a separate `Button` that does not stop row propagation; it performs the same navigation.
- **CTA mapping:**
  - `picking` → `Button variant="primary" size="sm"` label **Choose a game**.
  - `invited` / `draft` → `Button variant="outline" size="sm"` label **View details**.
- **Status badge mapping:** `draft` → `Badge variant="draft"`; `invited` → `Badge variant="invited"`; `picking` → `Badge variant="picking"`. Completed and cancelled sessions are not shown.
- **Attendee count:** display a horizontal stack of up to 3 confirmed-attendee `Avatar` (`size="sm"`) followed by a `Label` text: "{N} going" or "0 going" if empty. On mobile, show only the count text (the avatar stack may be hidden at `sm:` to save space).
- **Ordering:** backend-enforced order: `picking` first, then `invited` by `scheduledAt` ascending, then undated `draft` last; deterministic tie-break by `createdAt`.
- **Role-aware visibility:** backend only returns `invited` and `picking` for ordinary members; owners/admins also receive `draft`. The UI does not perform additional state filtering.
- **Empty state:** inside the sessions card, centered `EmptyState` with icon `material-symbols:inbox`, the role-aware heading/body, and an owner/admin-only "Create a night" CTA.

### Shared Collection Spotlight

- **Container:** `Card` with a `CardHeader` containing title "Shared collection spotlight" and a trailing `RouterLink` "Browse Library" (`text-primary text-sm font-medium hover:underline`).
- **Grid:** `grid grid-cols-2 md:grid-cols-4 gap-4` inside `CardContent`.
- **Compact card:**
  - Thumbnail: `aspect-[4/3] rounded-lg bg-surface-variant overflow-hidden` with `object-cover` image. Fallback shows "No image" centered in `text-on-surface-variant`.
  - Title: `text-sm font-medium line-clamp-2 text-on-surface`.
  - Rating: `Badge variant="invited"` with `average.toFixed(1)`.
  - Owner stack: `AvatarGroup` capped at 3 avatars (`size="sm"`) + `AvatarGroupCount` `+N` overflow.
- **Selection:** exactly four games, deterministically ordered by backend: owner count descending, then `average` descending, then name ascending. If fewer than 4 multi-owner games exist, single-owner games fill remaining slots by the same tie-breakers. Empty state only when the group collection has zero games.
- **Click behavior:** clicking a spotlight card opens the BGG page (`https://boardgamegeek.com/boardgame/{id}`) in a new tab, matching the existing `GameCard` behavior. "Browse Library" navigates to `/collection?group={inviteCode}` in the same tab.
- **Empty state:** inside the spotlight card, centered `EmptyState` with icon `material-symbols:inbox`, heading "The shared library is empty", body "Members’ collections will appear once they bind their BGG usernames." No CTA.

### Members Panel

- **Container:** `Card` with `CardHeader` title "Members" and `CardContent`.
- **List:** `space-y-2` of member rows. Each row is a flex container:
  - `Avatar` (`size="md"`) with `AvatarFallback` using `useMemberColor(user.username)`.
  - Display name: `text-sm font-medium text-on-surface`.
  - Role label: `text-xs uppercase tracking-wide text-on-surface-variant` (Owner/Admin/Member).
  - Action menu trigger: icon-only `Button variant="ghost" size="icon"` with `material-symbols:more_vert` and `aria-label="Actions for {displayName}"`. Only rendered when the current user has an authorized action for that row.
- **Action menu authorization:**
  - Owners: see role-change and remove options for every non-owner member (including admins). No menu on their own row or other owners.
  - Admins: see only the remove option for non-owner/non-admin members.
  - Members: no menu.
- **Action menu items:**
  - Role change: if target is currently `MEMBER`, show "Make admin"; if `ADMIN`, show "Change role to member". Uses the `updateGroupMemberRole` mutation.
  - Remove: `DropdownMenuItem variant="destructive"` label "Remove from group". Selecting it expands the inline confirmation panel instead of executing immediately.
- **Inline removal confirmation:** a panel immediately below the member row, `bg-error-container border border-outline rounded-lg p-4` with:
  - Text: "Remove {displayName}? They will be removed from the group and their games will no longer appear in the shared collection."
  - Buttons: `Button variant="destructive" size="sm"` **Remove** and `Button variant="outline" size="sm"` **Cancel**.
  - This is **not** a modal. Only one row can be in confirmation state at a time.

### Invite Card

- **Container:** `Card` with `CardHeader` title "Invite people" and `CardContent`.
- **Visibility:** rendered only for owners and admins (`group.myRole === 'OWNER' || group.myRole === 'ADMIN'`).
- **Invite link section:**
  - Read-only `Input` containing `{origin}/g/{inviteCode}`, `aria-label="Invite link"`.
  - Icon-only `Button variant="outline" size="icon"` with `material-symbols:content_copy` to copy the link.
  - Success text: "Copied!" in `text-primary text-sm` below the field, shown for 2 seconds after a successful copy.
  - ARIA: success text is wrapped in an `aria-live="polite"` region.
- **Visual separator:** `border-t border-outline` with `pt-4` between the link section and the email form.
- **Email invitation form:**
  - Email `Input` with placeholder "Email address" and `type="email"`.
  - Role `Select` with options "Member" (always) and "Admin" (owner only).
  - `Button variant="primary" size="default"` "Send invite".
  - Mutation error appears directly below the form as `text-error text-sm`.
- **Loading:** the send button shows `disabled:opacity-50` while `inviteToGroup` mutation is in flight.

### Loading States

- The page-level `GroupView` loading state renders skeletons instead of the hub:
  - Header: `Skeleton` title bar (width 1/2, height 32px) and a `Skeleton` description bar (width 2/3, height 16px).
  - Sessions card: `Skeleton` card with 3 stacked rows (each row: 56×56 square + two text bars + a small button bar).
  - Spotlight card: `Skeleton` card with a 4-column grid of 4 thumbnail rectangles and two text bars per card.
  - Members card: `Skeleton` card with 4 rows of circle + text bars.
  - Invite card: not shown during loading (role unknown); leave the side rail empty or show a single placeholder skeleton card.
- All skeletons use `bg-surface-variant animate-pulse rounded-md` from the `Skeleton` primitive.

### Error States

- `GroupView` error boundary: `EmptyState` heading "Couldn’t load this page", body "Please check your connection and try again.", icon `material-symbols:warning` (if available, otherwise `inbox`).
- Not-found / unauthorized: `EmptyState` heading "Group not found", body "This group doesn’t exist or you don’t have access to it.".
- Mutation errors (invite, role change, remove): inline text below the relevant form or menu, color `text-error`, 14px.

### Focus & Accessibility

- Focus ring: `focus-visible:ring-2 focus-visible:ring-primary focus-visible:ring-offset-2` on all interactive primitives (Button, Input, Select, DropdownMenu triggers, RouterLink focus states).
- Visible focus only (`focus-visible`); no persistent focus rings on click.
- Icon-only buttons must have explicit `aria-label` (copy link, member menu trigger, mobile menu toggle in shell).
- Session rows must be keyboard navigable: each row is a `button` or `RouterLink` with a single tab stop; the trailing CTA is a separate focusable control.
- Dropdown menus use reka-ui keyboard navigation (arrow keys, Enter, Escape, Tab trapping).
- Remove confirmation panel has `role="alert"` and focuses the "Cancel" button on open, or the first button if preferable.
- "Copied!" success is announced via `aria-live="polite"`.
- Heading hierarchy: page `h1` for group name, card titles use `h2`, section-internal headings use `h3` where needed.
- Color contrast: all text uses `on-surface` / `on-surface-variant` over the corresponding surface tokens; badges use the semantic alias pairs defined in Phase 5.

### Apollo Cache Interaction

- After a successful `createNightSession` mutation, the returned session is appended to the cached `Group.sessions` array via `cache.modify` so the new session appears without a full refresh.
- After a successful `removeGroupMember` mutation, the removed membership is evicted from the cached `Group.memberships` array via `cache.modify` (or `refetchQueries: ['Group']` as a fallback if the mutation payload does not return the removed ID).
- After `updateGroupMemberRole`, Apollo normalizes the returned membership object automatically; no additional manual cache update is required.
- After `inviteToGroup`, the invite card form resets (`email` cleared, role reset to `Member`); the pending invite is not displayed on the hub.

## Token Class Reference

Use these exact Tailwind v4 classes (all map to Phase 5 M3 tokens) in the new components:

- **Page background:** `bg-surface text-on-surface`.
- **Cards:** `rounded-xl border border-outline bg-surface-container shadow-card`.
- **Card hover:** `hover:shadow-md hover:-translate-y-1 transition-all duration-300` on interactive cards (spotlight, session rows).
- **Text hierarchy:** `text-on-surface` for primary text; `text-on-surface-variant` for secondary/helper text; `text-primary` for links and accent text; `text-error` for destructive text.
- **Badges:** `Badge variant="draft|invited|picking|completed"`.
- **Buttons:** `Button variant="primary|outline|ghost|destructive" size="default|sm|icon"`.
- **Inputs:** `Input` (already styled with `border-outline bg-surface focus:ring-primary`).
- **Avatars:** `Avatar` with `useMemberColor(username)` class; `AvatarGroup` for stacks; `AvatarGroupCount` for overflow.
- **Divider:** `border-t border-outline`.
- **Skeletons:** `Skeleton` with `bg-surface-variant`.
- **Focus ring:** `focus-visible:ring-2 focus-visible:ring-primary focus-visible:ring-offset-2`.
- **No hard-coded hex colors:** do not use `bg-indigo-*`, `text-neutral-*`, `bg-red-*`, etc. outside the token system.
