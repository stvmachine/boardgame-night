## Phase Goal

**As a** group member, **I want to** view the group's sessions, members, shared collection spotlight, and invite controls in one hub, **so that** group members can coordinate upcoming nights and shared games from one place.

<objective>
Publish the secure, role-aware Group sessions contract that the responsive hub consumes, without coupling backend resolver work to frontend page composition.

Purpose: Establish the hardest authorization and query-bounding constraint before the UI renders session data, while preserving the existing game-picking collection consumer.
Output: Role-aware Group sessions, eager-loaded attendee summaries, bounded/full GraphQL operations, regenerated schema/client artifacts, and a migrated GamePicker query consumer.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser → GraphQL Group query | An untrusted route token and authenticated viewer request role-sensitive session data. |
| Rails associations → GraphQL response | Group, session, and attendance rows cross the authorization and serialization boundary. |
| Schema source → generated client | Server fields become compile-time frontend contracts through schema dump and codegen. |

## STRIDE Threat Register (ASVS L1; block high)

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-08-01 | Information Disclosure | `GroupType#sessions` | high | mitigate | Require `viewer_role`, filter drafts and terminal states before serialization, and cover owner/admin/member/outsider contexts in `group_query_spec.rb`. |
| T-08-02 | Spoofing | invite-code lookup | high | mitigate | Derive role only from `context[:current_user]`, group owner id, and persisted membership; token knowledge alone returns no sessions. |
| T-08-03 | Denial of Service | nested attendance reads | medium | mitigate | Eager-load sessions/attendances/users in both lookup branches and consume loaded associations in `NightSessionType`. |
| T-08-04 | Tampering | schema/client publication | medium | mitigate | Generate SDL/JSON/TypeScript from source and require schema dump, codegen, and build to pass together. |
| T-08-SC | Tampering | package supply chain | low | accept | No package is installed; execution uses dependencies already locked and vetted in prior phases. |
</threat_model>
