<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser → member mutations | Untrusted group/user/role ids request destructive or privilege-changing operations. |
| Browser → inviteToGroup | Untrusted email/role input requests reusable invitation delivery. |
| Clipboard API → rendered feedback | Browser capability success/failure affects what the user believes was copied. |
| Apollo cache → recomputed group shelf | A destructive membership change must not leave stale member or ownership data visible. |

## STRIDE Threat Register (ASVS L1; block high)

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-08-09 | Elevation of Privilege | `removeGroupMember` / `updateGroupMemberRole` | high | mitigate | Preserve backend owner/admin/owner-only checks, protect owner rows, and test direct unauthorized calls for every role. |
| T-08-10 | Tampering | member/role ids and removal cache update | high | mitigate | Resolve target memberships inside the supplied group, return the actual removed membership id, and reconcile normalized Group fields only after success. |
| T-08-11 | Information Disclosure | reusable invite link | high | mitigate | Render link/copy controls only for owner/admin and preserve the backend owner/admin gate on invite delivery; test member absence and direct mutation denial. |
| T-08-12 | Spoofing | clipboard success message | low | mitigate | Announce success only after `navigator.clipboard.writeText` resolves; display failure feedback otherwise. |
| T-08-13 | Repudiation | destructive removal | medium | mitigate | Require explicit member-naming inline confirmation before mutation and keep mutation errors visible in the affected row. |
| T-08-SC | Tampering | package supply chain | low | accept | This plan installs no package and uses already-locked dependencies only. |
</threat_model>
