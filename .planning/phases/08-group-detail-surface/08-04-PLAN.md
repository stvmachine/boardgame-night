## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| URL query → Apollo query selection | User-controlled `group` and filter values choose the active collection data source. |
| GraphQL GroupCollection → collection UI | Authorized server data enters the shared filters/grid pipeline. |
| Filter state → browser history | UI state rewrites the URL while a security-relevant group token is present. |

## STRIDE Threat Register (ASVS L1; block high)

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-08-13 | Information Disclosure | `/collection?group=` data source | high | mitigate | Depend on Plan 08-03's server-side `viewer_role` guard and retain outsider GroupCollection regression coverage; frontend token parsing never grants access. |
| T-08-14 | Tampering | group/groupBy permalink state | medium | mitigate | Use an exact allowlist for legacy grouping values, reserve all other `group` values, and test preservation across every filter write. |
| T-08-15 | Denial of Service | duplicate Apollo queries | medium | mitigate | Use reactive `enabled` options so group and merged-user queries are mutually exclusive. |
| T-08-16 | Spoofing | collector identity hydration | low | mitigate | Hydrate controls only from server-returned group members with non-empty bggUsername values; do not trust a URL username list in group mode. |
| T-08-SC | Tampering | package supply chain | low | accept | No package is installed; routing, Apollo, and permalink behavior use the existing stack. |
</threat_model>
