## Phase Goal

**As a** suggestion engine developer, **I want to** parse and persist BGG `suggested_numplayers` poll data into normalized database tables, **so that** the Phase 7 engine can score games by community best-player-count fit instead of the min/max range heuristic.

<objective>
Establish the parse-and-persist foundation for BGG poll data: a migration creating `bgg_polls` / `bgg_poll_results` plus `poll_data_fetched_at` / `poll_data_error` on `bgg_things`, ActiveRecord models with associations, a `Bgg::Normalizer.normalize_polls` extension, and a `Bgg::PollPersister` service that upserts poll rows and stamps `poll_data_fetched_at`.

Purpose: This is the first vertical slice — BGG thing XML (from the existing `stevmachine_thing.xml` fixture) becomes structured, queryable DB rows. Phase 7 and the GraphQL layer (plans 06-02, 06-03) build on these models.
Output: Migration, two models, normalizer extension, poll persister service, and RSpec specs — all green against the existing fixture.
</objective>
