## Phase Goal

**As a** suggestion engine developer, **I want to** backfill and continuously enrich BGG poll data via rate-limited background jobs, **so that** every existing and newly imported BggThing has poll data available for Phase 7 scoring.

<objective>
Wire the poll data pipeline to live BGG: add per-thing-ID caching + 20-ID batching + XXE hardening to `Bgg::Client#thing`, create `Bgg::EnrichThingPollsJob` (auto-triggered after import) and `Bgg::BackfillPollDataJob` (one-time, rake-triggered), and hook the enrichment job into `ImportCollectionJob`.

Purpose: This slice proves the full vertical path — live BGG `/thing` XML → cached → parsed → persisted poll rows — under the existing global `bgg_api` concurrency lock and 1 req/5s rate limit.
Output: Two Solid Queue jobs, a rake task, the client caching extension, and RSpec specs (webmock-stubbed, no live BGG calls).
</objective>

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-06-01 | Tampering / Information Disclosure | Bgg::Client#thing XML parsing | high | mitigate | parse_xml uses Nokogiri `config.strict` + `config.nonet` — blocks external entity network access and DOCTYPE-based SSRF/file disclosure. |
| T-06-03 | Denial of Service | BackfillPollDataJob / EnrichThingPollsJob | medium | mitigate | Batch size capped at 20 (BGG hard limit), `find_in_batches` keeps memory bounded, `limits_concurrency to: 1, key: "bgg_api"` serializes all BGG jobs, and `Bgg::RateLimiter` enforces 1 req/5s. |
| T-06-05 | Denial of Service | BggThing poll_data_fetched_at loop | medium | mitigate | PollPersister always stamps poll_data_fetched_at after a successful fetch even when no poll rows exist (Pitfall 5); backfill only selects `where(poll_data_fetched_at: nil)` so enriched rows are never re-fetched. |
| T-06-04 | Information Disclosure | GraphQL / job error logging | low | accept | Job errors are logged server-side only (Rails.logger); no BGG response bodies are surfaced to clients. GraphQL exposure is plan 06-03's concern. |
| T-06-SC | Tampering | npm/pip/cargo installs | n/a | accept | No new packages installed (RESEARCH Package Legitimacy Audit: none new). |
</threat_model>
