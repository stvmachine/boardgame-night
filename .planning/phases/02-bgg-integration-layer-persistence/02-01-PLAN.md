    - `Bgg::ClientError` (4xx client errors)
    - `Bgg::ServerError` (5xx server errors)
    - `Bgg::NetworkError` (timeout, connection failures)
    - `Bgg::ParseError` (XML parse failures)
    - `Bgg::RateLimitedError` (when rate limit is exceeded)
    - `Bgg::QueuedResponse` (internal signal for the 202 retry loop — not a user-visible error)

    - `Bgg::ResourceNotFound` (BGG endpoint returned 404)
    - `Bgg::InvalidUsernameError` (BGG user doesn't exist)

    **D-03, D-04:** Create `app/services/bgg/rate_limiter.rb`:

    - `INTERVAL = 5.seconds`, `CACHE_KEY = "bgg:last_request_at"`
    - `#throttle { ... }` block interface: reads `Rails.cache.read(CACHE_KEY)`, if elapsed &lt; INTERVAL then sleep for the remainder, then `Rails.cache.write(CACHE_KEY, Time.now.to_f, expires_in: 10.seconds)`
    - `#reset!` method that deletes the cache key (for tests)
    - Use `Process.clock_gettime(Process::CLOCK_MONOTONIC)` for timing to avoid wall-clock skew from NTP adjustments (per RESEARCH.md pattern). But store `Time.now.to_f` in the cache since cache values are serialized and must survive process restarts.
    - Per D-20: rate limiter tests use `freeze_time` + manual cache manipulation to verify timing without sleeping. Test: 1) first call passes immediately, 2) second call within 5s sleeps, 3) after 5s+ passes again, 4) `reset!` clears state.

    **D-01, D-05, D-06, D-17, D-18:** Create `app/services/bgg/client.rb`:

    - `BASE_URL = "https://boardgamegeek.com/xmlapi2"`, `USER_AGENT = "BoardgameNight/1.0.0 (boardgame-night.app)"`, `TIMEOUT = 10`
    - Constructor: `attr_reader :conn, :rate_limiter`. Accepts `rate_limiter: Bgg::RateLimiter.new`.
    - Faraday setup:
      - `Faraday.new(url: BASE_URL, request: { timeout: 10, open_timeout: 5 })`
      - Request middleware: `f.request :retry, { max: 3, interval: 1.0, interval_randomness: 0.5, backoff_factor: 2, retry_statuses: [429, 502, 503] }` (D-05)
      - Header: `f.headers["User-Agent"] = USER_AGENT` (D-06, BGG-06)
      - Response middleware: `f.response :raise_error` (raises Faraday::ClientError on 4xx, Faraday::ServerError on 5xx)
      - Adapter: `f.adapter :net_http`
    - `#collection(username)` — calls `request_with_202_retry(:collection, username: username, own: 1, stats: 1)`, returns Nokogiri::XML::Document. The params `own: 1, stats: 1` ensure only owned games + stats are returned (D-17).
    - `#thing(ids)` — accepts single ID or array of IDs, joins with comma, calls rate_limiter.throttle { conn.get("/thing", { id: ids_string, stats: 1 }) }, returns Nokogiri::XML::Document (D-07, BGG-07).
    - `#search(query, type: "boardgame", exact: false)` — params { query:, type: }, adds `exact: 1` if exact is true, returns Nokogiri::XML::Document (D-17).
    - `#user(username)` — calls rate_limiter.throttle { conn.get("/user", { name: username }) }, returns Nokogiri::XML::Document (D-18).
    - **202 Retry loop** (`#request_with_202_retry`, D-06, BGG-03):
      - **CRITICAL: `request_with_202_retry` is a PUBLIC method** — it is consumed by `Bgg::CollectionFetcher` in Plan 03 (Wave 3). Do not mark it private.
      - Wraps the rate_limiter.throttle block
      - Checks `response.status == 202` — if so, raises `Bgg::QueuedResponse`
      - Catches `Bgg::QueuedResponse` outside the throttle: increments retry counter, sleeps 5s, retries up to 5 times
      - If exhausted, raises `Bgg::CollectionNotReadyError`
      - IMPORTANT: The 202 retry count is per-request, not cumulative. Each 202 attempt IS rate-limited (it goes through throttle) — this means a worst-case 202 sequence takes 5 × (5s sleep + 5s throttle window) = ~50s.
    - `#parse_xml(body)` — wraps Nokogiri::XML in strict mode, catches SyntaxError → raises Bgg::ParseError.
    - Error mapping:
      - `Faraday::ResourceNotFound` → `Bgg::ResourceNotFound`
      - `Faraday::ClientError` (4xx, not 404) → `Bgg::ClientError`
      - `Faraday::ServerError` (5xx) → `Bgg::ServerError`
      - `Faraday::TimeoutError`, `Faraday::ConnectionFailed` → `Bgg::NetworkError`
    - ALL error classes are defined in errors.rb — the client only references them by name.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Rails app → BGG API | Outbound HTTPS to boardgamegeek.com/xmlapi2. BGG is untrusted upstream — responses may be malformed, delayed (202), or contain unexpected data. |
| BGG token in ENV | BGG_TOKEN loaded from .env.bggeek. Must never appear in logs, error messages, or responses. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-01 | Spoofing | Bgg::Client → BGG API | medium | mitigate | Faraday enforces HTTPS via default SSL verification; no cert pinning needed for v1 |
| T-02-02 | Tampering | BGG XML response parsing | medium | mitigate | Nokogiri strict mode rejects malformed XML; Bgg::ParseError wraps failures; no blind trust of BGG content |
| T-02-03 | Information Disclosure | BGG_TOKEN in error messages | high | mitigate | All Faraday errors are caught and re-raised as custom Bgg::Error subclasses that strip URL/header/body context. Bgg::Client never includes BGG_TOKEN in logged params. |
| T-02-04 | Denial of Service | Bgg::Client without rate limiter | high | mitigate | Every public method wraps in rate_limiter.throttle. RateLimiter is injected via constructor — cannot be bypassed. |
| T-02-05 | Tampering | BGG description HTML | low | accept | BGG game descriptions may contain HTML. Raw HTML is stored in `raw_data` JSONB; rendering is Phase 3's responsibility with sanitization. Not addressed in Phase 2. |
| T-02-SC | Tampering | Ruby gem supply chain | high | mitigate | All gem packages verified in RESEARCH.md §Package Legitimacy Audit as [OK]. No [SUS] or [SLOP] packages. |
</threat_model>
