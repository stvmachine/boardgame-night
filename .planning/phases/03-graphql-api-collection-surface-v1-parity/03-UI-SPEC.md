|-------|------------------|------------|

| 1 | `bg-green-500` | `text-white` |
| 2 | `bg-purple-500` | `text-white` |
| 3 | `bg-orange-500` | `text-white` |
| 4 | `bg-pink-500` | `text-white` |
| 5 | `bg-teal-500` | `text-white` |
| 6 | `bg-red-500` | `text-white` |
| 7 | `bg-yellow-500` | `text-black` |
| 8 | `bg-cyan-500` | `text-white` |
| 9 | `bg-indigo-500` | `text-white` |
| 10 | `bg-lime-500` | `text-black` |
| 11 | `bg-emerald-500` | `text-white` |
| 12 | `bg-rose-500` | `text-white` |
| 13 | `bg-violet-500` | `text-white` |
| 14 | `bg-sky-500` | `text-white` |

Hash algorithm (ported from `memberColors.ts`):
```ts
let hash = 0;
for (const char of username) {
  hash = (hash << 5) - hash + char.charCodeAt(0);
  hash = hash & hash;
}
const index = Math.abs(hash) % 15;
```

## 6. Information Architecture

### Routes

| Route | View | Layout | Notes |
|-------|------|--------|-------|
| `/` | `LandingView.vue` | Centered hero + topbar | Username input + hot games grid |
| `/collection` | `CollectionView.vue` | Topbar + sidebar + main grid | Permalink state in query params; search is a panel here |
| `/hot` | `HotView.vue` | Topbar + main grid | Dedicated hot/trending games page |

### Navigation

- Topbar is present on all routes.
- Topbar left: app logo/name (`BoardGame Night`) linking to `/`.
- Topbar center/right: nav links **Collection**, **Hot**.
- Topbar right (mobile): hamburger icon toggles sidebar drawer.
- Topbar right (desktop): compact username input for quick add (optional; main input lives in sidebar).

### URL State (Permalinks)

`history.replaceState` updates silently on every change. Only non-default values are written.

| Param | Format | Default | Example |
|-------|--------|---------|---------|
| `usernames` | comma-separated | none (required) | `usernames=alice,bob` |
| `owners` | comma-selected | all users | `owners=alice` |
| `q` | string | "" | `q=wingspan` |
| `players` | 1–10 integer | "" | `players=4` |
| `time` | 1–6 bucket | "" | `time=3` |
| `complexity` | 1–4 bucket | "" | `complexity=2` |
| `sort` | `name_asc` default | `name_asc` | `sort=rating_desc` |
| `group` | `none` default | `none` | `group=rating` |

Omission rules per D-16:
- `sort=name_asc` → omitted
- `group=none` → omitted
- empty `q`, `players`, `time`, `complexity` → omitted
- `owners` omitted when it equals the full `usernames` list

## 9. Interaction Patterns

### Collection Import Flow (D-09)

1. User enters username(s) in landing or sidebar input.
2. Frontend calls `validateBggUsername` for each username.
3. Valid usernames are automatically submitted via `importCollection` mutation.
4. `collectionSynced` subscription is opened for each username.
5. Sidebar shows status cards with badges and game counts.
6. Game grid renders partial data from `READY` users while others sync (stale-while-revalidate).
7. On failure, per-user error card appears with Retry button.

### Search

- Fuse.js client-side search over merged collection.
- Keys: `name`, `name.text`, `originalname`.
- Threshold: `0.3`.
- Debounce: `300ms` via `@vueuse/core` `useDebounce`.
- Min search length: `0` (filters as you type).

### Filters

| Filter | UI control | Values | Logic |
|--------|------------|--------|-------|
| Players | Native `<select>` | 1–10 | `minPlayers ≤ n ≤ maxPlayers` |
| Playing time | Native `<select>` | 1–6 buckets | Match by `maxPlaytime` bucket |
| Complexity | Native `<select>` | Light ≤2, Medium 2–3, Medium-Heavy 3–4, Heavy ≥4 | Match by `averageWeight` bucket |

### Sort

| Value | Label |
|-------|-------|
| `name_asc` | Name: A-Z |
| `name_desc` | Name: Z-A |
| `rating_asc` | Rating: Lowest first |
| `rating_desc` | Rating: Highest first |
| `year_asc` | Year: Oldest first |
| `year_desc` | Year: Newest first |
| `complexity_asc` | Complexity: Light → Heavy |
| `complexity_desc` | Complexity: Heavy → Light |

### Group

| Value | Label |
|-------|-------|
| `none` | None |
| `players` | Number of Players |
| `rating` | Rating Range |
| `bestPlayers` | Best with X Players |

Grouping logic is ported from `grouping.ts`:
- `players`: range string, sorted by min player count.
- `rating`: 9.0+, 8.0–8.9, 7.0–7.9, 6.0–6.9, Below 6.0, Unrated.
- `bestPlayers`: heuristic upper-2/3 of player range.

### Owner Toggles (D-15)

- Each member card has a checkbox.
- Selected owners filter which games appear.
- `owners` URL param encodes selected usernames.
- Select All / Deselect All buttons in Collectors section.

### Refresh Cooldown (D-12)

- Manual refresh button per user.
- 15-minute cooldown after each refresh.
- Disabled state shows remaining time as `Refresh (14m 32s)`.
- Stale data remains visible while refresh runs.

### Permalink Sync (D-14)

- `filterStore` is the source of truth.
- A `watch` or `useUrlSearchParams` listener writes to `history.replaceState` after every change.
- On page load, URL params hydrate the store before the GraphQL query fires.
- No explicit Share button; users copy the URL.

## 10. State Management

### Pinia Stores (UI-only)

#### `useFilterStore`

```ts
interface FilterState {
  usernames: string[];
  selectedOwners: Set<string>;
  query: string;
  players: number | null;
  timeBucket: number | null;
  complexityBucket: number | null;
  sort: SortOption;       // default 'name_asc'
  group: GroupOption;     // default 'none'
}
```

- Persists filter state to `localStorage` via `@vueuse/core` `useStorage` so a refresh restores UI choices (but URL still wins on first load).
- Never holds server data.

#### `useUiStore`

```ts
interface UiState {
  sidebarOpen: boolean;     // mobile drawer
  collapsedSections: Record<string, boolean>;
  collapsedGroups: Set<string>;
}
```

#### `useDraftUsernamesStore`

```ts
interface DraftState {
  landingInput: string;
  sidebarInput: string;
}
```

### Apollo Cache (server data)

- `mergedCollection` query result goes into Apollo `InMemoryCache`.
- `hotItems`, `search`, `user` cached with standard fetch policies.
- `importCollection` mutation updates cache entries via refetch or optimistic response.
- `collectionSynced` subscription updates `UserSyncStatus` fragment in cache.

## 11. Loading, Empty, and Error States

### Global Loading

- Initial data fetch: show skeleton cards in grid + spinner in sidebar status cards.
- Landing hot games: skeleton thumbnails.

### Per-User Loading

- Status badge: **Syncing…** (amber).
- Game count shows last known count or `-`.
- Card border pulse optional.

### Empty States

| Condition | Heading | Body | Visual |
|-----------|---------|------|--------|
| No usernames | No collectors selected | Enter one or more BoardGameGeek usernames to merge collections. | Icon + dashed box |
| No selected owners | No collectors selected | Select at least one collector to see games. | Icon + dashed box |
| Filters yield zero results | No games found | Try clearing filters or selecting more collectors. | Magnifying-glass icon |
| Valid username but empty BGG collection | {username} has no games | Their BGG collection appears to be empty. | Empty shelf icon |

### Error States

| Condition | Treatment |
|-----------|-----------|
| Invalid username | Inline banner below input; does not fire import |
| Import failed (per user) | Red status card with error message and Retry button |
| GraphQL network error | Top banner: "Unable to reach server. Please check your connection and try again." |
| Hot games error | Section message: "Failed to load hot games" with retry link |

## 13. Accessibility

- All interactive elements keyboard-focusable.
- Focus rings: `focus:outline-none focus:ring-2 focus:ring-indigo-500 focus:ring-offset-2`.
- Color is never the sole indicator; sync status uses icon + text + color.
- Owner avatars have `title` and `aria-label` with username.
- Drawer uses `aria-modal="true"`, `aria-labelledby` pointing to drawer title, traps focus.
- Toggle buttons use `aria-expanded`.
- Select inputs have associated `<label>`.
- Skeletons use `aria-busy="true"` on parent region.
- Reduced motion: respect `prefers-reduced-motion` by disabling translate transitions (use `motion-safe:` variants).

## 14. Owner Color Assignment System

### Composable: `useMemberColor`

```ts
// app/frontend/composables/useMemberColor.ts
const PALETTE = [
  { bg: 'bg-blue-500', text: 'text-white' },
  // ... 14 more entries
];

export function useMemberColor(username: string) {
  const index = hashUsername(username) % PALETTE.length;
  return PALETTE[index];
}
```

### Usage

- `MemberAvatar.vue` uses the composable.
- Sidebar member cards use larger avatar.
- Game card owner row uses `size="xs"` avatars.
- Same username always resolves to same color across sessions.
