## Phase Goal

**As a** board game night organizer, **I want to** manually refresh a collector's BGG collection with a 15-minute cooldown and see when it was last synced, **so that** I can get fresh data without hammering the BGG API.

<objective>
Close Gap 3 from 03-VERIFICATION.md: No refresh button in the UI, no per-user cooldown enforcement, and no stale-while-revalidate caching for the BGG collection fetch. Add a per-user refresh button with last-synced timestamp in the sidebar, enforce a 15-minute cooldown per username in the importCollection mutation, persist last_synced_at on the User model, and cache BGG collection responses with stale-while-revalidate.

Purpose: Delivers the manual refresh + cooldown + stale-while-revalidate behavior promised by COLL-18 and D-12.
Output: last_synced_at migration, cooldown-enforced mutation, cached BGG client collection fetch, RefreshButton component, useRefreshCollection composable.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser → Rails /graphql mutations | Untrusted refresh input crosses here; validated by contract + cooldown. |
| Rails → boardgamegeek.com | External API egress with credentials and rate limits; cached responses. |
| Rails → Rails.cache | Cache store for BGG collection XML; server-side only. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-10-01 | Denial of Service | importCollection mutation spammed | high | mitigate | 15-minute per-username cooldown check in mutation resolve; Solid Queue limits_concurrency to 1 for bgg_api key; Bgg::RateLimiter 1 req/5s. |
| T-03-10-02 | Tampering | BGG cache poisoning | medium | mitigate | Cache key is server-computed from username (no user-controlled key); cache stores Nokogiri documents only; cache is server-side Rails.cache, not browser-accessible. |
| T-03-10-03 | Information Disclosure | last_synced_at timestamp exposed via GraphQL | low | accept | Timestamp is non-sensitive metadata; helps users decide when to refresh. |
| T-03-10-04 | Repudiation | refresh action not logged | low | accept | Refresh is a user-initiated read-refresh; no audit requirement for v1 friend-group app. |
