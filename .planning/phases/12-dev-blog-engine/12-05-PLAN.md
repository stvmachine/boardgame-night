  <action>
    Create `app/controllers/blog_controller.rb` with two actions: `index` serves `public/dev-blog/index.html` for requests to the blog subdomain; `show` serves `public/dev-blog/posts/<slug>/index.html` for a slug parameter. In both actions, resolve the requested path within `public/dev-blog/` using `Rails.public_path.join`, verify the resolved path is a descendant of `public/dev-blog/` (e.g., by checking `realpath.to_s.start_with?(public_dir.realpath.to_s)`), and return `head :not_found` if the file is missing or escapes the directory. Use `send_file` with `type: 'text/html', disposition: 'inline'`. Set `response.headers['Cache-Control'] = 'public, max-age=300'` for static HTML. In `config/routes.rb`, add a `constraints` block matching the blog host pattern chosen in ADR-014 (e.g., `host: /blog\./` or `host: /dev-blog\./`) that maps `root` to `blog#index` and `get '*slug', to: 'blog#show', format: false`. Also add a path fallback on the primary domain: `get '/blog', to: 'blog#index'` and `get '/blog/*slug', to: 'blog#show', format: false`. Place these routes before the SPA catch-all so the Vue router does not intercept them. Create `spec/requests/blog_controller_spec.rb` that verifies: (a) a request to the blog host root returns 200 with the index HTML; (b) a request to the blog host with a known slug returns 200 with the post HTML; (c) a request for a missing slug returns 404; (d) a path traversal attempt (e.g., `../../../etc/passwd`) returns 404; (e) the `/blog` path fallback works on the primary host; (f) the SPA catch-all does not intercept `/blog` routes. Ensure `public/robots.txt` exists and allows blog indexing.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser / Kamal proxy → BlogController | Host header and slug parameter cross the trust boundary |
| BlogController → public/dev-blog/ | Static files are read from disk and returned to the client |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-12-05-01 | Elevation of Privilege | Host header spoofing to access app routes on blog host | medium | mitigate | Routes are constrained by host pattern; the app catch-all is placed after blog routes. The blog host only serves static blog files. |
| T-12-05-02 | Information Disclosure | Path traversal via slug parameter | high | mitigate | BlogController resolves the requested path under `public/dev-blog/` and verifies it is a descendant; escapes return 404. |
| T-12-05-03 | Information Disclosure | Dotfiles or non-HTML files served from public/dev-blog/ | medium | mitigate | Only `.html` files are served; requests with path components containing `..` or non-HTML extensions return 404. |
| T-12-05-04 | Denial of Service | Large static file read | low | mitigate | Files are small HTML/CSS; send_file streams from disk. |
| T-12-05-05 | Security Misconfiguration | Blog subdomain not covered by TLS | medium | mitigate | Kamal proxy handles TLS for all configured hosts; the certificate must include the blog subdomain. |
</threat_model>
