<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Repository markdown → pure-Ruby builder | Frontmatter and body data become public HTML. |
| Generated file → Rails response | Only the generated allowlisted index may cross into an HTTP response. |
| RubyGems lock resolution → image dependency set | One new gem becomes executable build code. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-12-01-01 | Elevation of Privilege | `DevBlog::PostParser` | high | mitigate | `Psych.safe_load` permits only Date beyond primitives, forbids aliases/symbols, and has a spec rejecting object tags and aliases. |
| T-12-01-02 | Tampering | `DevBlog::MarkdownConverter` / ERB boundary | high | mitigate | Reject raw HTML and unsafe URI schemes, escape every metadata value, and allow unescaped insertion only for converter-produced body HTML under spec. |
| T-12-01-03 | Information Disclosure | Plain-Ruby build | high | mitigate | Do not boot Rails/dotenvx or read ENV; build under sentinel credentials and scan generated HTML for both sensitive names and values. |
| T-12-01-04 | Tampering | `kramdown` dependency | medium | mitigate | Add only the ADR-selected gem, commit its Bundler lock resolution, and run `bundler-audit`. |
| T-12-01-05 | Denial of Service | Missing generated index | low | accept | A missing file returns 404 rather than reading another path; Docker/CI later make absence a build failure. |
</threat_model>
