## Trust Boundaries

| Boundary | Description |

| CI runner → repo | CI runs the blog build and tests; the build must not leak secrets |
| Generated HTML → browser | Static content is served publicly; it must not contain secrets or executable code |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-12-06-01 | Information Disclosure | Secrets in generated HTML | high | mitigate | Verification test greps for `DOTENV_PRIVATE_KEY_BGGEEK`, `BGG_TOKEN`, and literal `.env.bggeek` values; CI fails if any are found. |
| T-12-06-02 | Denial of Service | CI job blocking merges | medium | mitigate | Blog CI job is lightweight (<60s) and runs only `spec/lib/dev_blog/`; it does not depend on E2E or external services. |
| T-12-06-03 | Information Disclosure | Human verifies public blog content | low | accept | The human review confirms no sensitive project details are published; posts contain only public architecture and code excerpts. |
| T-12-06-04 | Tampering | Blog content modified after CI but before deploy | low | mitigate | The deploy builds the blog from committed markdown inside the Docker image; the generated output is part of the immutable image. |
</threat_model>
