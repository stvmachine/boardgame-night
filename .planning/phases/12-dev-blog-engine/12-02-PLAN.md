    Create `lib/dev_blog/post.rb` defining `DevBlog::Post` as a value object with readers for `title`, `date`, `slug`, `description`, `tags`, `body`, `draft?`, `content_html`, and `url`. Create `lib/dev_blog/post_parser.rb` with a `DevBlog::PostParser.parse(path)` class method that reads the file, splits YAML frontmatter from the markdown body using a regex that matches `---\n...---\n`, parses the YAML with `Psych.safe_load` (or `YAML.safe_load`) with `permitted_classes: [Date, Time]`, and validates required fields (`title` and `date`). Derive `slug` from the filename (basename without a leading `YYYY-MM-DD-` date prefix) or from a `slug` frontmatter override. Convert `date` to a `Date`. Create `lib/dev_blog/markdown_converter.rb` that wraps the markdown parser chosen in ADR-014 (e.g., kramdown) and converts a markdown string to HTML. Raise `DevBlog::InvalidPost` with a clear message if required fields are missing or the file is malformed. Do not evaluate user-provided code from frontmatter or body. Add `spec/lib/dev_blog/post_parser_spec.rb` with tests covering: valid post parsing, missing frontmatter error, slug derivation from filename and override, tag defaulting, and conversion of the existing auth post.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Markdown source → parser | Post content and frontmatter cross from repo into the SSG engine |
| Template → renderer | ERB templates are evaluated with a restricted binding |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-12-02-01 | Code Execution | YAML frontmatter parsing | high | mitigate | Use `Psych.safe_load` or `YAML.safe_load` with no or minimal permitted classes; do not call `eval` or `instance_eval` on frontmatter values. |
| T-12-02-02 | Code Execution | ERB templates | medium | mitigate | `TemplateRenderer` uses a clean binding with only provided locals and `html_escape`; no access to ENV, filesystem, or arbitrary Ruby methods. |
| T-12-02-03 | Information Disclosure | Draft posts in public output | medium | mitigate | `Site` filters out posts with `draft: true` unless `ENV["DEV_BLOG_INCLUDE_DRAFTS"]` is set. |
| T-12-02-SC | Tampering | Package legitimacy of the new markdown parser | medium | mitigate | Only install the gem named in ADR-014; verify the gem name on rubygems.org before adding to Gemfile in Plan 12-03. |
</threat_model>
