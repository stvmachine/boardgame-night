- Created a failing authenticated HTTP GraphQL acceptance test that exercises the full request → auth → resolver → engine → typed response path.
- Added `time_budget_minutes` and `complexity_preference` columns to `night_sessions` with safe defaults.

## Decisions Made

- Followed the plan's locked D-01..D-15 formulas exactly, including the A1/A2 smoothing and fallback interpretations.
- Kept the engine stateless and side-effect-free: all data is passed in, so the unit tests need no Dataloader or GraphQL context.
- Reused the existing `Loaders::PollsLoader` and `Loaders::OwnersLoader` in the resolver with `load_all` to avoid N+1 queries.
- Returned `nil` from `suggestions` for non-picking states and `[]` when there are no attendees, matching D-08/D-09.
- Added `time_budget_minutes` and `complexity_preference` as plain Int/String fields rather than enums, matching the current plan scope; 07-02 may introduce a complexity-preference enum if needed.

### Test-Data Correction (not a deviation)

- During Task 2 engine verification, the original request and engine fixtures used poll data at player_count=4 while the seeded sessions had two Going attendees (attendee_count=2). This caused the range-midpoint fallback to score 0 at the range edge, filtering out all candidate games. The fixture data was corrected to target player_count=2 so the tests exercise the intended poll-based scoring path. The plan's RED/GREEN intent was preserved and the change was committed as part of Task 3.

## Issues Encountered

- The initial engine spec fixtures targeted the wrong player count (4) for two attendees (2). Correcting the fixture player count resolved all scoring failures without engine changes.
- No synchronous BGG calls, package installs, or architectural changes were required.
