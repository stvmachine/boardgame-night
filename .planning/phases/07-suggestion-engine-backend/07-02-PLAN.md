## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| GraphQL mutation input → dry-validation contracts | Untrusted numeric/string preference values enter the application. |
| Authenticated caller → NightSession row | A caller attempts to mutate a session identified by client-controlled ID. |

## STRIDE Threat Register (ASVS L1; block high)

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-07-05 | Spoofing | all preference mutations | high | mitigate | Reuse the GraphQL controller's Bearer-derived `context[:current_user]`; every resolver rejects a missing identity and mutation specs cover anonymous calls. |
| T-07-06 | Elevation of Privilege | `updateSessionPreferences` / `scheduleSession` | high | mitigate | Compare `session.host_id` to current user before any update; tests cover group members and outsiders. |
| T-07-07 | Tampering | time/complexity inputs | medium | mitigate | Use dry-validation as the sole boundary, whitelist all five strings, require a positive integer, update only explicit keys, and backstop with model validations. |
| T-07-08 | Repudiation | preference edits | low | accept | Preferences are reversible before picking and ActiveRecord `updated_at` records modification time; an actor-by-actor audit log is not proportionate for non-sensitive planning metadata. |
| T-07-SC | Tampering | package supply chain | low | accept | No dependency installation occurs in this plan. |
</threat_model>
